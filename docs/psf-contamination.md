# 점광원 잡음이 PSF 측광을 무너뜨리는 경로와 방어선

**2026-07-29 실측** · 데이터: LCO 0.4m tfn / sq32 = QHY600 CMOS, M67 B·V 60 s ×10
(archive.lco.global) · 보정: APEX 산술(BANZAI 대조 0.35~0.85%)

## 1. 무슨 일이 일어났나

우주선·핫픽셀 제거를 끈 채 처리했더니 **PSF 측광이 구경 측광의 32% 밖에 못
잡았다.** 그런데도 `[UNIT] flux sanity OK` 를 찍었다 — 조용히 틀린 값이 나온다.

연쇄는 이렇다.

1. **CMOS 검출기는 점광원 잡음이 많다.** 검출 중 FWHM ≤ 1.5 px 비율:
   Sinistro CCD **0.0%** · M13 Moravian CMOS 7.3% · M3 Moravian CMOS 15.4% ·
   M67 QHY600 CMOS **40.0%**.
2. **ePSF 참조별 선택 기준이 「밝고 고립」이다.** 우주선이 정확히 그 기준의
   최적해다 — 플럭스가 1 픽셀에 몰려 피크가 최고이고, 이웃이 없어 고립도도 만점.
3. **형태 필터가 유일한 방어선인데 상시 무력화된다.** `epsf_sharp` 컷 상한이
   0.80 인데 실제 별의 sharpness 중앙값은 0.87~0.97 이다. 통과율이
   6.8~27.9% 에 그쳐 목표 수를 못 채우고, 그러면 코드가 필터를 **통째로
   폐기**한다(`step8_psf_photometry.py`, "relaxed to pre-morph pool").
   M13·Sinistro·M67 로그가 전부 완화로 갔다 — 설계대로 작동한 적이 없다.
4. **그 결과 ePSF 가 실제 별보다 2.75배 좁아진다.** half-max 픽셀 수
   9개(M67) vs 78개(Sinistro) vs 188개(M13). NEA 8.7~18.4 px vs 88.4 px.

CCD 가 무사했던 것은 필터가 작동해서가 아니라 **주울 우주선이 없어서**였다.

## 2. 방어선 세 겹

| 방어선 | 무엇을 하나 | 픽셀을 바꾸나 |
|---|---|---|
| **Step 0 우주선 제거** | astroscrappy(L.A.Cosmic)로 스파이크 정정 | **예** |
| **FWHM 하한** | 참조별은 프레임 FWHM 의 절반 이상 | 아니오 |
| **PSF 대칭 판정** | 좌우 또는 상하 양쪽 이웃이 피크의 30% 이상 | 아니오 |

PSF 대칭 판정(`apex.analysis.psf_policy.psf_symmetric_mask`)은 AstralImage 의
cosmetic 엔진(`_extended_bright_cores`)에서 가져왔다. 거기서는 핫픽셀 보정에서
**별을 보호**하는 데 쓰지만 여기서는 **별이 아닌 것을 배제**하는 데 쓴다.
피크 자신과 비교하므로 밝기와 무관하고, FWHM 측정 없이 픽셀만으로 판정한다.
실측: astroscrappy 가 CR 로 지목한 45,433곳 중 **67.3% 차단, 별 736개 100% 보존**.

## 3. 어느 방어선이 얼마나 듣나 (M67 대조 실험)

| 조건 | PSF/구경 플럭스비 | MAD | 프레임간 rms |
|---|---:|---:|---:|
| CR 없음 · 방어선 없음 | **0.317** | 0.070 | 0.336 |
| CR 없음 · 방어선 있음 | 0.44 ~ 0.79 | — | — |
| **CR 있음 · 방어선 있음** | **0.985** | **0.0074** | **0.045** |

**방어선은 CR 제거의 대체재가 아니다.** 0.317 → 0.65 수준까지 끌어올리지만
정상값 0.985 에는 못 미친다. 하늘이 어두운 B 필터(31 e⁻)가 V(75 e⁻)보다 나쁘다
(0.44 vs 0.78) — 배경 대비 스파이크가 도드라질수록 오염이 심하다.

→ **CR 제거가 근본 대책이고, 나머지 둘은 잔여 오염(위성 궤적·고스트·잔여
우주선)용 안전망이다.** 셋 다 켜 두는 것이 현재 기본값이다.

## 4. CR 제거가 별을 깎지 않는가

M67 B 프레임의 별 749개(flux > 500 e⁻)를 CR 전후로 구경측광해 비교했다.

| 부류 | N | 중앙값 변화 | 해석 |
|---|---:|---:|---|
| 코어에 CR 마스크 걸림 | 45 (6%) | **−0.44%** | 실제 손실 |
| 코어 깨끗 (하늘 환형만 정리) | 704 (94%) | **+0.07%** | 증가 479 / 감소 225 |

94% 는 별이 깎인 것이 아니라 **하늘 환형에서 우주선이 빠져 배경 과대추정이
걷힌 것**이다(증가가 감소의 2배). 실제 손실은 코어가 마스크된 6% 뿐이고, 그중
상당수는 진짜로 우주선이 별 위에 떨어진 경우다.

단, 언더샘플 필드(FWHM < 2 px)에서는 별 자체가 스파이크로 오인될 수 있으므로
이 결론을 그대로 옮기면 안 된다. 여기 데이터는 FWHM 4.7~7.8 px 였다.

## 5. 우리 자료에서 CR 제거를 켜면 무엇이 달라지나 (2026-07-30)

같은 raw 를 **Step 0 부터 두 번** 처리해 나란히 비교했다(마스터도 각각 새로
만들었으므로 완전히 독립된 두 경로). 도구: `validation/psf_crossinstrument/
compare_cr_effect.py`.

| | **M13** (구상, 15장) | **NGC6811** (산개, 21장) |
|---|---|---|
| 점광원 잡음 FWHM≤1.5px | 6.1% → **1.6%** | 1.3% → **0.4%** |
| **측광 Δmag (CR후−CR전)** | **+0.0002** (MAD 0.0038) | **+0.0012** (MAD 0.0039) |
| 별-프레임 쌍 (양쪽 SNR>20) | 12,248 | 19,141 |
| SNR 중앙값 | 43.8 → 43.9 | 56.5 → 57.1 |
| 마스터 소스 | 1,574 → 1,501 | 2,127 → 1,943 |
| **1프레임 검출** | 233 → **176** (−24%) | 357 → **183** (−49%) |
| **전프레임 검출** | 433 → **432** (−1) | 397 → **396** (−1) |
| PSF 플럭스비 (검출된 별) | 1.077 → 1.076 | 1.064 → 1.069 |
| PSF 프레임간 rms | 0.0694 → **0.0506** | 0.0546 → 0.0585 |

**두 성단에서 같은 패턴이다.** 측광값은 1 mmag 이내로 보존되고, 전프레임
검출(진짜 별)은 정확히 1개씩만 줄며, 1프레임 검출만 대폭 사라진다. SNR 은
오히려 미세하게 오른다(하늘 환형이 깨끗해져서).

1프레임 검출 감소폭이 NGC6811 에서 더 큰 것은 프레임 수 때문이다 — 21장이라
우주선이 마스터에 들어갈 기회가 많았고(357개), 제거 후 **176 vs 183 으로 절대수가
수렴**한다. 남은 것이 진짜 문턱 별이라는 방증이다.

> **측광 대조는 반드시 하늘 좌표로 짝지어야 한다.** 재처리하면 마스터가 다시
> 만들어져 `master_id` 가 재할당된다(M13: 1574 → 1501). ID 로 조인하면 다른 별끼리
> 짝지어져 MAD 가 1.24 mag 이라는 불가능한 값이 나온다. 좌표(1″)로 재면 0.0038 이다.

### D-004 에 미치는 영향

기존 전제는 「1프레임 검출의 절반이 우주선이니 컷 2 로 자르자」였는데, 이제 그
우주선이 Step 0 에서 **24~49% 걸러진다**. 컷 2 를 걸면 남은 176~183개 중 진짜
문턱 별을 버리는 비중이 그만큼 커진다 — **컷을 완화하거나 1 로 유지하는 쪽 논거가
강해졌다.** 결정을 다시 판단할 것.

## 6. 남은 것

- **`epsf_sharp` 컷 기본값(0.30~0.80)이 실제 별과 안 맞는다.** 대칭 판정이
  뒤를 받치므로 급하지는 않지만, 근본적으로는 프레임 sharpness 분포에서
  유도해야 한다. 지금은 컷이 사실상 항상 완화된다.
- **아직 재처리하지 않은 성단이 남아 있다.** M13·NGC6811 은 CR 켜고 다시 돌렸고
  기존 산출물은 `result_nocr/`·`sci_nocr/` 로 보존해 두었다. **M67·M3·M5 는
  아직 CR 없이 만든 상태**다(M3 는 오염 15.4% 로 가장 심한데 step7 이 없어
  직접 비교 대상이 아니었다).
### 함정 — PSF/구경 플럭스비는 검출된 별로만 재야 한다

한때 「NGC6811 의 PSF 플럭스비가 0.958~20.2 로 요동한다」고 적었으나 **오진이었다.**
비율의 분포는 이봉이고, 두 무리를 가르는 것은 `forced_flag` 하나다.

| | 정상군 (비율<2) | 폭주군 (비율>5) |
|---|---:|---:|
| `forced_flag` | 전부 False | **전부 True** |
| 개수 (0003-R) | 834 | 1,060 |
| 구경 플럭스 | 10,328 | 1,706 |
| 구경 SNR | 42.3 | 7.8 |

강제 측광 위치는 그 프레임에서 검출되지 않은 어두운 별이라 구경이 거의 0 을
재고, 그러면 비율이 폭주한다. 섞어서 중앙값을 내면 **강제 측광 비율이 높은 자료가
「PSF 이상」으로 보인다** (NGC6811 은 강제 56%). 검출된 별만 쓰면:

| 플럭스비 (검출된 별) | CR 전 | CR 후 |
|---|---:|---:|
| M13 | 1.077 | 1.076 |
| NGC6811 | 1.064 | 1.069 |

둘 다 정상이고 서로 차이도 없다. `compare_cr_effect.py` 는 이제 `forced_flag` 가
False 인 별만 쓴다. 지표가 자료 구성에 따라 흔들리면 그 지표가 부적합하다는 신호다.
