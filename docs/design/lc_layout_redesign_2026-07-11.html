공통 원칙 — "플롯이 주인공, 컨트롤은 사이드"

  1. 2-컬럼 통일: 좌측 고정폭(340px) 컨트롤 컬럼 + 우측 플롯/결과 영역(stretch). 이미 tools가 쓰는 문법 — step 창도 같은 문법으로 통일해 인지 비용 제거.
  2. 좌컬럼은 QScrollArea: 컨트롤이 아무리 쌓여도 창 최소 높이를 밀어올리지 못함 → 어떤 화면에서도 잘림 물리적으로 불가. 목표: 전 창 최소 높이 ≤ 720px.
  3. 플롯은 항상 stretch=1 + tame_canvas: 잔여 공간을 전부 플롯이 가져감.
  4. 배너 다이어트: 사용법 안내 배너(스텝당 2~3줄)는 ⓘ 가이드 팝업으로 이미 존재 → 창에서는 제거. 상태 배너(Target/Comp)는 좌컬럼 1줄로.
  5. 기능 제거 없음: 모든 기존 컨트롤·단축키·상태는 그대로, 위치만 이동 (철칙 2).

선택지: A안 = 위 재배치 (권장) / B안 = 현행 구조 유지 + 전체를 QScrollArea로 감싸기만 (잘림은 없어지지만 플롯 비중·버튼 산개는 그대로 — 근본 해결 아님).

Tools 공통 원칙 — "사이드패널은 불변, 탭은 플롯만 갈아끼움"

지적된 문제: 탭을 바꿀 때마다 사이드패널 구성이 달라지거나(variable_star의 Refine/Multi-Mode), 컨트롤이 겹치고, 버튼이 많아 시선이 분산.

  1. 좌패널 고정 3섹션 + 순서 통일: ① 데이터 (Workspace/Load/Use data/Filter) ② 설정 (해당 도구의 파라미터) ③ 실행 (primary 1개 + 보조). 탭을 바꿔도 좌패널은 절대 안 바뀜.
  2. 탭 고유 컨트롤은 우측 플롯 위 1줄만 (예: Phase Plot 탭의 Period/T₀). 2줄 이상 필요하면 설계 재검토.
  3. 버튼 다이어트: 도구당 primary 1개. "1.Load 2.Scan 3.Single 4.Multi" 같은 단계 버튼 열거(variable_star)는 단일 진행 버튼 + 진행 상태 표시로. 이미 다른 버튼으로 실행 가능한 중복 버튼 제거 대신 비활성+툴팁 (철칙 10).
  4. 빈 공간 금지: 좌패널 마지막 섹션 아래는 stretch가 아니라 Log(접힘)가 바닥 고정.

적용 대상: variable_star(미커밋 alias 작업 커밋됨 — 안전) → transit → eb → merger 순. merger는 상단 Step1~6 탭바를 메인 창 스텝리스트와 같은 문법(중립 행+상태바)으로.
