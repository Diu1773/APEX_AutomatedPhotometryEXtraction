# 헤드리스 실행이 그림을 낸다 — 무엇이 없었고 무엇을 넣었나

2026-08-18. 사용자: *"헤드리스로 돌렸을때 plot도 다 뽑아지니?"* → 세어보니 아니었다.
*"걍 gui plot이랑 똑같이 저장하게만 하라는 거긴했는데 어차피 데이터는 다 있을거아니야
run돌리면"* → 맞았다. 데이터는 다 있었고 저장 코드만 창 안에 있었다.

## 왜 그랬나 — 층 문제

    apex/analysis   savefig  8곳    <- 헤드리스도 돈다
    apex/pipeline   savefig  0곳
    apex/gui        savefig 32곳    <- 창을 열어야 돈다

**그림 저장 코드의 80 % 가 GUI 층에 있었다.** Step 8·10 만 계산부에 있어서 헤드리스에서
나왔다. 설정이 창에 갇혀 있던 것, 계산이 `QThread` 안에 있던 것과 정확히 같은 모양이다.

## 렌더해봐서 잡은 결함 넷

그림을 실제로 띄우지 않으면 전부 조용히 통과했을 것들이다.

1. **Step 4 첫 그림이 통째로 비었다.** 숫자는 다 있는데 `qc_status` 가 없어서 마스크가
   전부 비었고 제목만 "PASS=0 REVIEW=0 FAIL=0". `evaluate_frame_qc` 는 이미
   `apex.analysis` 에 있었는데 **창만 불렀다.**
2. **Step 4 x 축이 Index 였다.** 창은 airmass 로 그린다. `headers.csv` 가 디스크에
   있으므로 결합해 같은 축을 쓴다.
3. **Step 7 성장곡선 payload 에 프레임 이름이 없었다.** 창은 사용자가 클릭한 행에서
   알았지만 배치는 payload 밖에 없어 제목도 파일명도 못 만든다.
4. **Step 12 가 서비스가 만든 Figure 를 버렸다.** `make_figures=True` 로 받아놓고
   요약 JSON 만 썼다. 즉 나이는 내고 그 그림은 안 냈다.

## Step 5 는 무엇을 넣을지부터 측정으로 정했다

창에도 그림이 없었으므로 "GUI 와 똑같이"가 성립하지 않는다. 그래서 후보 지표가 실제
데이터에서 얼마나 흔들리는지 재고 골랐다 — 다섯 성단 137 프레임.

| 지표 | 변동계수 | 채택 |
|---|---|---|
| `resid_vs_radius_slope` | **1.75** | ○ 패널 ② |
| `match_rate_cat` | 1.12 | △ 패널 ③ 색 |
| `center_offset_arcsec` | 0.73 | ○ 패널 ④ |
| `edge_resid_ratio` | 0.68 | ○ 패널 ② |
| `resid_mad_px` | 0.47 | — |
| `rms_px` | 0.35 | ○ 패널 ① |
| `n_match` | 0.30 | ○ 패널 ③ |
| `scale_delta_pct` | 0.05 | ✕ 제목에 숫자로 |
| `inlier_rate` | 0.02 | ✕ 제목에 숫자로 |
| `match_rate` | **0.01** | ✕ **평평한 직선** |

**변동이 없는 지표에 축을 주면 아무 말도 안 하는 직선이 된다.** 그 세 개는 제목 줄에
숫자로 넣고, 자리는 말을 하는 패널에 줬다.

### 그리고 그 그림이 바로 하나를 판별했다

`resid_vs_radius_slope` 중앙값이 **음수**(−0.42)였다. 잔차가 시야 중심에서 크고
가장자리로 갈수록 작아진다는 뜻인데, 광학 왜곡은 보통 반대다. 후보는 둘 —
SIP 차수 부족(광학) 또는 성단 중심부 혼잡(측정).

성단 종류로 갈랐다.

| 성단 | 종류 | radius 기울기 | edge/centre |
|---|---|---|---|
| M13 | 구상 | −0.419 | 1.233 |
| M3 | 구상 | −0.475 | 1.349 |
| M5 | 구상 | −0.209 | 1.105 |
| M67 | 산개 | **+0.058** | 1.052 |
| NGC 6811 | 산개 | **+0.072** | 1.072 |

**혼잡이다.** 성긴 장에서는 0 근처의 작은 **양수** — 잔여 왜곡이 예측하는 방향 그대로다.
뭉친 장에서만 음수로 뒤집힌다. 즉 SIP 해는 멀쩡하고, 구상성단 중심부가 중심 측정을
망치고 있다.

두 지표가 어긋나 보였던 것(음의 기울기인데 edge/centre > 1)도 같이 풀린다:
구상성단에서는 **중심과 가장자리가 둘 다** 중간대보다 나쁘다 — 중심은 혼잡 때문,
가장자리는 잔여 왜곡 때문이다.

이건 오늘 구경 실험이 내린 결론(혼잡이 성단 장의 지배 오차)과 같은 방향이고, 서로
독립적인 측정이다.
