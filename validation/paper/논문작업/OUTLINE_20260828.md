### 다시 쓴 하나 — 3.1

앞 판은 **곱**이었다(기존 구현인가 × 민감도). 곱은 인자 하나가 0 에 가까우면
결과가 0 이 되고, **실제로 이번 개정에서 프레임 품질 검사의 검증 절이 사라졌다** —
자작 판정이고 `fig6_qc_validation.py` 가 이미 있는데도.

**바닥값 + 가중치**로 바꾼다.

1. **모든 단계에 면제 없는 바닥** — 3.3 의 계약 검사. 단위와 눈금 · 마스크·포화·
   NaN 전달 · 오차 배열 구성 · 좌표 원점 규약(SEP·photutils 0 시작, IRAF 1 시작) ·
   버전 고정과 회귀 시험
2. **그 위에 얼마를 더 쌓을지**를 3.2 의 민감도가 정한다

그리고 **이분이 아니라 세 갈래**다 — 라이브러리 호출 + 기본 파라미터 / 라이브러리
호출 + APEX 가 파라미터 결정 / APEX 자작 계산. **가운데가 가장 많고 앞 규칙은
가운데를 첫째 칸으로 밀었다**(검출은 SEP 를 부르지만 문턱값·배경격자·디블렌딩은
APEX 가 정한다).

3.1 이 반드시 담아야 할 것 둘이 더 있다.

  **3.3–3.15 를 돌리기 전에 확정했음을 명시한다**

  때문이다 — 같은 편향을 타면 일치는 검증이 아니다

### 3.2 에 추가할 것

앞 판은 주입 셋(프레임 상수·색·위치)이었다. 심사가 넷을 더 요구했고 전부 이
프로젝트가 이미 겪은 현상이다.

- **밝기 의존 편향** — 어두운 쪽 밴드별 편차. 주계열 하단을 밀어 **나이를 직접
  흔든다.** 가장 중요한 누락
- **대기질량 상관 추세** — 프레임 상수는 차등측광이 지우지만 이건 안 지워지고
  다중밤에서 가짜 주기가 된다. `m_ij = s_i + z_j + k1·X_j` 에서 두 항이 축퇴한다
- **혼잡도** — 구상성단에서 밀도는 반지름 함수라 위치 주입과 축퇴
- **측성(위치) 오차** — 주입이 전부 등급 공간이라 **3.5·3.7 에 민감도 숫자가 안
  나온다. 자작 비중이 가장 큰 두 단계가 규칙 바깥에 있었다**

그리고 **주입마다 「하류를 다시 돌렸나 고정했나」를 표에 적는다.** 프레임 상수
주입은 다시 돌리면 민감도 0, 고정하면 1 이고 **중간이 없다.** 두 경우를 다 싣는다.

**분해 회수 검사**도 넣는다 — 색만 주입했을 때 위치항이 0 으로 나오는가. 없으면
「셋을 분해했다」는 주장에 근거가 없다.

### 이동 하나 — 재현 가능성

앞 판은 3 절 열세 절 중 열두 번째였다. **재현성은 오차 항이 아니라 소프트웨어의
성질이고, 27 쪽 원고의 20 쪽 언저리는 찾으러 온 사람이 못 찾는 자리다.**

「계산 비용」만 3 절에 남기고(3.15), 「반복 실행이 같은 값을 내는가」는 소프트웨어
가용성 옆으로 옮겨 한 절로 세운다. 거기에 **잠금 파일(91 개 전부 `==`) · scipy
사건 · 어긋남 방지 검사 · 재현 절차**를 한자리에 놓는다.

**scipy 사건은 이 논문에서 APEX 밖으로 일반화되는 유일한 결과다** — 동일 코드의 두
실행 사이에서 PSF 측정 22,305 개 중 다섯이 4.8e-05 mag 움직였고 원인이
scipy 1.18.0 대 1.17.1 이었으며, 다섯 다 이미 불량으로 걸러진 별이라 발표 그림에
안 들어갔다. 증상·원인·대응·재발 방지가 다 갖춰졌다.
