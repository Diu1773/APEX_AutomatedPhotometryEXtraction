## 초록

소형·중형 지상망원경으로 얻은 성단·변광성 자료는 여러 raw 프레임의 보정, 검출, WCS,
반복 측광을 거쳐 CMD 또는 광도 곡선으로 사용할 수 있다. 실제 작업에서는 이
단계들이 서로 다른 프로그램과 설정 파일로 나뉘어 있어, 같은 별을 여러 프레임에서
추적하고 중간 선택을 다시 확인하는 일이 별도의 작업이 된다. APEX(Automated
Photometry EXtraction)는 이 흐름을 하나의 데스크톱 소프트웨어로 묶는다. 사용자는
raw CCD 영상을 입력하고 bias·dark·flat 보정, 프레임 QC, 천체 검출, WCS, 마스터
목록, 강제 구경 측광 또는 PSF 측광을 거쳐 CMD 모드나 다중야간 light-curve(LC)
모드로 이동한다.

APEX의 GUI는 각 단계의 파라미터와 중간 산출물을 보여 주고, 계산부는 Qt와 분리된
모듈로 실행한다. GUI에서 선택한 값과 처리 결과는 manifest와 signature에 기록되며,
같은 입력을 헤드리스 경로에서 다시 실행할 수 있다. 검출·구경 적분·PSF 적합·좌표
변환에는 SEP, photutils, Astropy, SciPy를 사용하고, 내장 quad WCS, PDM, SYSREM,
참조별 선택을 포함한 구경 보정은 APEX의 처리 순서와 QC 규칙을 구현한다.

검증은 주입 참값, 독립 코드, 외부 파이프라인과의 비교로 구성하였다. Python
`ccdproc`, IRAF `ccdproc`, BANZAI와 비교한 검출기 보정은 단계별 절대 통계에서
일치하였다. M13 8개 프레임의 WCS 비교에서 내장 경로의 Gaia 잔차 중앙값은
0.346 px(0.137 arcsec)였고 ASTAP과 astrometry.net은 0.493 px(0.195 arcsec)였다.
내장 경로의 프레임당 시간은 11.1 s로 ASTAP 3.1 s보다 길었으므로 정확도와 속도를
따로 보고한다. PDM은 PyAstronomy `pyPDM`의 선택 주기와 $2.8\times10^{-4}$일
이내에서 일치했고, SYSREM은 독립 갱신식으로 계산한 지배 계통성분을 재현하였다.
주입 측광의 pull 표준편차는 1.014였으며, 독립 구경 측광과의 MAD는 합성 자료에서
0.006 mag, NGC 6811 실측 자료에서 0.0097 mag였다.

이 논문은 raw 입력에서 최종 CMD·LC까지 이어지는 한 소프트웨어의 처리 경로와 그
중간 판단을 기록하는 방법을 제시하고, 각 단계가 독립 기준과 어느 범위에서 맞는지
수치로 제시한다. 검증 범위는 사용한 검출기·배경·시상·천체 밀도와 실행 조건에
한정되며, 강한 공간 배경, 분해 한계보다 작은 겹침, 기기 간 절대 보정의 일반성,
외부 prior 없는 등시선 복원은 포함하지 않는다.

**핵심어:** 측광 기법 · 자료 분석 방법 · 소프트웨어 · 산개성단: 개별(NGC 457, NGC 6811) · 구상성단 · 변광성: $\delta$ Scuti

## 1. 서론

소형·중형 지상망원경 관측에서 성단의 CMD나 변광성의 LC를 만들려면 여러 raw 프레임에서
같은 별을 반복 측정해야 한다. 보정 프레임을 선택하고, 프레임의 품질을 확인하고,
천체 목록과 WCS를 만든 뒤, 같은 위치에서 모든 프레임의 밝기를 읽어야 한다. 마지막
산출물이 CMD인지 LC인지에 따라 비교성 선택, 영점 보정, 주기 분석을 추가한다.

여기서 소형·중형이라는 표현은 이 연구가 실제로 검증한 0.4–1 m급 관측 자료의 범위를
가리킨다. APEX의 입력 계약과 계산부는 특정 망원경 모델에 고정되지 않으며, 다른 기기의
적용 여부는 검출기 조립·보정 자료와 관측 조건을 별도로 확인해야 한다(부록 B, 5.3절).

IRAF/DAOPHOT \citep{stetson1987, tody1986, tody1993}, SExtractor \citep{bertin1996},
Astropy \citep{astropy2013, astropy2018, astropy2022}와 photutils \citep{photutils}는
이 과정에 필요한 개별 연산을 제공한다. PhotometryPipeline \citep{mommert2017},
ASTROPOP \citep{campagnolo2019}, prose \citep{garcia2022}는 여러 연산을 자동화한
파이프라인이고, AstroImageJ \citep{collins2017}와 HOPS \citep{tsiaras2019}는 GUI에서
시계열 측광을 다룬다. 그러나 사용자가 한 프로그램 안에서 raw 입력부터 CMD와 LC
중 하나를 선택해 처리하고, 그 과정에서 정한 값과 중간 결과를 다시 확인하는 흐름은
별도로 설계해야 한다.

APEX는 이 작업 흐름을 하나의 소프트웨어로 구성한다. 공용 단계는 raw 입력에서
검출기 보정, 프레임 QC, 천체 검출, WCS, 마스터 목록, 강제 구경 측광과 PSF 측광까지
진행한다. 이후 CMD 모드에서는 영점·색항 보정과 등시선 표시를, LC 모드에서는
비교성 선택·차등 광도 곡선·detrending·주기 분석을 수행한다. 사용자는 단계 창에서
값을 확인하고 바꿀 수 있으며, 각 선택은 실행 기록과 중간 산출물에 남는다. 계산부는
GUI와 분리되어 같은 자료를 헤드리스로 다시 처리할 수 있다.

최근 PhoPS \citep{erece2026}처럼 자동 측성과 측광을 하나로 묶는 파이프라인도
등장했다. 이 논문에서 APEX의 위치는 특정 기능의 최초성을 주장하는 데 있지 않다.
APEX가 제공하는 raw→CMD/LC 공용 흐름, GUI에서의 중간 판단 기록, 외부 엔진을 선택할
수 있는 WCS 경로, 그리고 같은 계산부를 헤드리스 검증에 사용하는 구조를 하나의
실행 기록으로 묶어 제시하는 데 있다.

본 연구는 다음을 확인한다. (1) raw 프레임에서 CMD와 LC까지의 공용 단계가 실제
산출물을 만드는지, (2) 각 단계의 핵심 수치가 주입 참값·독립 코드·외부 목록과 어느
범위에서 일치하는지, (3) GUI에서 정한 파라미터와 헤드리스 실행이 같은 계산 결과로
이어지는지, (4) APEX 고유 모듈이 표준 라이브러리와 어떤 경계에서 결합되는지다.
알고리즘의 성능 순위를 비교하는 논문은 아니다. 한 소프트웨어 안에서 처리한 전체
경로를 단계별 증거와 함께 평가한다.

이에 따라 본 논문은 다음과 같이 구성된다. 2절에서는 APEX의 설계 요구사항과 raw
입력에서 CMD·LC로 갈라지는 공용 처리 흐름을 기술한다. 3절에서는 검출기 보정부터
검출, WCS, 측광, 시계열 모듈까지 단계별 검증 결과를 제시한다. 4절에서는 변광성
광도 곡선 사례로 전체 처리를 실증하고, 5절에서는 확인한 범위와 확인하지 못한
범위를 구분한다. 6절에서 결론을 제시한다.

## 2. 설계와 구현

### 2.1 소프트웨어 설계 요구사항

APEX의 설계는 두 가지 요구를 동시에 만족해야 한다. 측광 도구를 처음 다루는 사용자가 절차를 따라갈 수 있어야 하고, 산출된 측광값은 연구에 사용할 수 있는 수준이어야 한다. 아래 세 가지 요구사항이 구현 전반을 규정하며, 이 절의 나머지는 각 요구사항이 코드 구조에 어떻게 반영되었는지 기술한다.

**(i) 처리 순서와 파라미터를 사용자에게 제시한다**(그림 1). 작업 흐름은 고정된 단계열로 구성되며, 각 단계는 사용자가 값을 하나씩 확인하거나 지정하도록 요구한다. 사용할 보정 프레임(0단계), 프레임 채택 여부(3단계), 검출 문턱값(4단계), 별 확정에 필요한 최소 검출 프레임 수(6단계), 구경 반지름(7단계)이 이에 해당한다. 각 값이 어느 단계에서 어떤 근거로 정해졌는지는 실행 후에도 추적할 수 있다.

**(ii) 단계마다 독립적으로 확인 가능한 산출물을 기록한다.** 각 단계는 정해진 경로에 결과를 저장하며, 중간 단계부터 다시 실행할 수 있다. 이 구조에서 각 단계를 개별적으로 평가할 수 있고, 3절의 검증도 같은 단위로 구성하였다.

**(iii) 계산은 GUI와 분리한다.** 검출·측성·측광 계산은 Qt에 의존하지 않는 모듈에 두고, GUI는 이 모듈을 호출한다. 이 분리로 공용 과정에서는 3절의 헤드리스(headless) 검증과 사용자가 GUI로 수행하는 처리가 동일한 코드를 실행한다.

### 2.2 계층 구조

APEX는 그래픽 표현 계층과 계산 계층을 분리하였다. PyQt5로 작성한 그래픽 계층은 작업 흐름을 순서 있는 단계 창으로 제시하고, 파일 선택과 자르기, sky preview, 모드별 분석 같은 상호작용을 담당한다. 계산이 무거운 단계, 곧 천체 검출과 astrometric solution, 강제 측광은 Qt를 호출하지 않는 별도 모듈(`apex.analysis`)에 두었고, `apex.pipeline`이 그 실행 순서를 관리한다. 따라서 GUI를 띄우지 않고 헤드리스로도 같은 처리를 실행할 수 있다.

이 분리는 3절의 검증이 성립하는 조건이다. 공용 과정(0–7단계)에 대해서는 3절의 벤치마크와 검증 코드가 그래픽 계층이 호출하는 것과 같은 함수를 호출한다. 헤드리스 러너가 단계 순서를 정하고, 선행 조건을 확인하며, 각 단계를 멱등적으로 실행하고 실행 내역을 JSON으로 남긴다. CMD 모드의 PSF 측광(8단계)은 계층 구분이 다르다. EPSF 구성과 적합은 단계 창 모듈에 있고 `apex.analysis`에는 반복 판정과 품질 지표를 두었다. 다만 이 단계도 별도 스크립트로 창 없이 같은 처리 코드를 실행할 수 있으므로, 검증이 사용자 실행과 같은 코드를 확인한다는 점은 달라지지 않는다. 이 경로는 Qt 이벤트 루프만 만들고 화면을 띄우지 않는다.

### 2.3 표준 라이브러리와 APEX 고유 처리의 경계

APEX의 공용 측광 단계는 SEP, photutils, Astropy, SciPy가 제공하는 연산을 호출하고,
그 결과를 다음 단계에서 사용할 수 있는 자료구조와 QC 규칙으로 연결한다. 천체 검출,
구경 적분, PSF 적합, FITS·좌표·시간 처리에는 해당 라이브러리를 사용한다. APEX가
추가한 모듈은 기존 연산을 바꾸기보다, raw 입력에서 CMD 또는 LC까지 이어지는 순서와
사용자 선택을 한 실행으로 기록하는 역할을 한다.

내장 quad 솔버는 `astropy.wcs`가 제공하지 않는 blind plate solving을 담당한다. 이
경로는 APEX의 기본 WCS 경로이며, ASTAP과 astrometry.net은 사용자가 선택할 수 있는
외부 옵션이다. 외부 솔버를 선택하면 해당 프로그램의 초기해를 읽고 APEX의 동일한
Gaia 매칭·refine·QC 절차를 적용한다. 따라서 사용자는 외부 실행 파일이 설치된
환경과 설치되지 않은 환경에서 같은 단계 구조를 유지할 수 있다.

PDM은 사용 중인 Astropy 시계열 API에 없는 연산이라 자체 구현하였다. SYSREM은
\citet{tamuz2005}의 갱신식을 사용하되, 결측값·오차 가중치·대상별 신호
보존을 포함한 APEX의 입력 규칙을 적용한다. 구경 보정은 photutils의 성장 곡선 계산에
참조별 선택, S/N·포화 판정, 보정 상한과 실패 시 fallback을 추가한 단계다. 이 모듈들은
photutils, Astropy, SciPy, NumPy를 함께 사용하며, 계산 원시함수를 동일한 이름의
새 구현으로 교체하지 않는다. 구현상의 비용 제어는 quad 일괄 검색, PDM 배치 계산,
보정 스택 청크 처리, 고정 하늘 배경 재사용처럼 각 자료 경로에 필요한 부분에만
적용한다.

NaN 통계에는 `apex.utils.fast_stats`라는 호환 계층을 사용한다. Bottleneck은 core
의존성으로 선언되어 있으며, 보정·검출·cosmetic correction의 일부 큰 배열 통계를
Bottleneck으로 보내고 import에 실패하면 NumPy로 대체한다. 측광·WCS·시계열·overscan의
작은 계산은 NumPy를 직접 호출한다. 따라서 Bottleneck은 전체 파이프라인의 일괄 가속
기능보다 선택된 reduction의 실행 경로다.

자체 모듈은 API가 제공하지 않는 연산, 외부 실행 환경을 줄여야 하는 단계, APEX의
입력·QC 계약을 표현해야 하는 단계에 배치하였다. 내장 WCS는 오프라인 기본 경로로,
PDM은 Astropy API에 없는 분석으로, SYSREM은 결측·가중치·대상별 신호 보존 규칙을
포함한 분석으로, 구경 보정은 참조별 선택과 실패 처리를 포함한 측광 단계로 구현했다.
이 모듈들의 정확도는 3절에서 WCS 엔진 비교, 독립 측광, PDM·SYSREM 대조로 확인한다.

이 구분에 따라 3절의 검증을 구성하였다. 라이브러리가 담당하는 단계는 해당
라이브러리의 문헌과 종단 산출물로 확인하고, APEX가 추가한 모듈은 독립 기준과
직접 비교한다. 각 단계가 무엇에 기대고 그 검증이 3절 어디에 있는지는 표 1에
정리하였다.

### 2.4 공용 측광체인 (Step 0–7)

APEX는 검출기 보정을 선택적 첫 단계(Step 0)로 수행한다. 마스터 bias·dark·flat을 만들거나(중앙값 또는 시그마클립 결합) 미리 만든 마스터를 받아 $\mathrm{calibrated} = ((\mathrm{raw}-\mathrm{bias}) - k\,\mathrm{dark})/\mathrm{flat} + \mathrm{pedestal}$ 로 적용하며, 선택적으로 오버스캔 제거와 우주선·핫픽셀 제거(L.A.Cosmic)를 수행한다. 측광값에 영향을 주는 연산만 포함하였고, 영상 감상을 위한 처리(CFA 디모자이크, 프레임 합성, 국소 정규화, 행·열 결함 평탄화)는 넣지 않았다. 이들 연산은 화소값을 국소적으로 바꾸므로 측광 오차 모형이 성립하지 않는다. APEX는 모노 과학 CCD를 대상으로 한다.

Step 0은 폴더를 하나 지정하면 하위 경로의 FITS 헤더를 모두 읽어 각 프레임을 bias·dark·flat·light로 분류한다. `IMAGETYP` 계열 키워드를 먼저 보고, 값이 없으면 파일명으로 판정한다. 분류한 프레임은 관측 밤, 노출, 검출기 온도($\pm1\,^\circ$C), 필터로 묶이며, light 프레임은 노출과 온도가 맞는 dark, 필터가 맞는 flat과 자동으로 짝지어진다. 관측 밤의 경계는 관측지 경도를 반영한 지역 정오로 잡는다. UTC 정오로 나누면 동아시아 관측지에서 초저녁 프레임이 전날 밤으로 분류되기 때문이다. bias는 밤과 무관한 전역 풀로 두고, 해당 밤에 dark나 flat이 없으면 전역 풀에서 가져온다. 사용자는 이 분류 결과를 트리로 확인하고 필요하면 고친 뒤 실행한다. 이 단계는 3.2절에서 검증한다. 기본 검증 경로는 raw 프레임에서 Step 0을 실행하며, 이미 보정된 프레임을 가진 사용자는 이 단계를 건너뛸 수 있다.

1–3단계는 자료를 정리한다. FITS 파일을 고르고 헤더를 훑어 대상과 기기를 파악하며, 기준 영상에 공통 자르기 영역을 정해 전체에 적용하고, sky preview 단계에서 눈으로 확인하는 한편 프레임 품질을 자동으로 평가한다(3.3절에서 검증).

천체 검출(4단계)에서는 세 가지 검출 엔진 가운데 하나를 선택한다. SEP 라이브러리\citep[SExtractor 백엔드;][]{bertin1996}, photutils의 영상 분할\citep[`detect_sources`·`deblend_sources`;][]{photutils, astropy2022}, `DAOStarFinder`가 그것이며, 세 가지 사전 설정(보통·밀집·희미)이 파라미터를 정한다. 천체는 배경 RMS의 배수로 지정한 문턱값 위에서 찾는다. 이 논문의 검증은 SEP 엔진(3.2σ)을 쓴다. 검출기는 GUI 실행과 헤드리스 실행이 공유하는 하나의 구현이다.

5단계에서는 각 프레임의 astrometric solution을 구한다. 헤드리스 기본 경로와 GUI의 기본 선택은 외부 프로그램 설치 없이 완전히 오프라인으로 동작하는 내장 quad 솔버이다(표 1). 이 내장 경로를 기본으로 둔 이유는 ASTAP 실행 파일과 별도 별 데이터베이스, astrometry.net의 실행 파일·인덱스·WSL 또는 네트워크에 의존하지 않고 같은 입력에서 재현 가능한 기준 해를 얻기 위해서다. ASTAP \citep{astap}와 느리지만 견고한 astrometry.net blind 해 \citep{lang2010}는 별도 탭/옵션으로 선택하는 외부 엔진이며, 외부 탭을 선택한 경우에만 실행된다. ASTAP 탭에서 fallback을 켠 경우에 한해 ASTAP 실패 뒤 astrometry.net을 시도한다. 구한 해는 수용 기준을 통과해야 채택된다. 검출된 천체와 Gaia \citep{gaia_dr3_2023}를 교차매칭하여 각 해를 검증하고(교차매칭한 별 수, 매칭·inlier 비율, 시그마 클리핑한 잔차 RMS를 기록하며) 고정 문턱값(교차매칭한 별 20개 이상, 잔차 RMS 2.5 px 미만, 99퍼센타일 잔차 5 px 미만)을 넘지 못하면 기각한다. 통과한 해는 기준 화소를 옮겨 Gaia와의 중앙 오프셋을 상쇄해 정제하고, 잔차는 각 프레임의 FITS 헤더에 기록하여 처리 이력을 추적할 수 있게 한다. 좌표 변환에는 `astropy.wcs` \citep{astropy2013} 를 쓴다. 6단계는 프레임마다의 검출을 하나의 마스터 목록으로 합쳐, 이후 모든 프레임에서 측광할 위치를 고정한다.

강제 구경 측광(7단계)은 마스터 목록의 모든 천체를 각 프레임의 목록 위치에서 측광한다. 원형 구경으로 부분 화소까지 반영하여 플럭스를 재고, 하늘 배경은 동심 고리(annulus)에서 추정하며, 여기에 `photutils` \citep{photutils} 의 구경을 쓴다. 기본 구경 반지름은 프레임에서 잰 FWHM에 따라 정해지고($r_{\rm ap} = \max(4\,{\rm px},\, 0.8\,{\rm FWHM})$), 하늘 고리는 대략 4–6 FWHM에 걸친다. 반지름은 모두 조정할 수 있으며, 3.8절에서 구경 선택의 영향을 실측으로 평가한다. 오차는 완전한 CCD 방정식을 따라 천체와 배경의 포아송 잡음, 배경 추정 오차, 읽기 잡음을 합쳐 구하고, 보고된 오차와 실측 산포의 일치 여부는 3.7절에서 평가한다. 측광은 한 프레임 안의 천체들에 대해서는 벡터화하고 프레임끼리는 병렬로 처리하는데, 병렬 작업 수는 컴퓨터가 정한다(코어의 75%, 상한 있음). 그래서 1600만 화소 프레임 수백 장에 이르는 하룻밤 자료도 한 번에 처리한다.

SNR에 맞춘 고정 구경은 별빛의 일부만 담고 그 비율이 시상에 따라 흔들리므로, 각 프레임을 공통 total-flux 척도로 보정한다. APEX는 이 구경 보정을 프레임 안의 밝고 외딴 별들의 성장 곡선으로 만들어 모든 천체의 플럭스·오차에 적용하며, 프레임별 보정값과 기준별 수를 기록하여 처리 이력을 추적할 수 있게 한다. 보정을 단독으로 벤치마크하지는 않지만, 3.9절의 교차 확인이 보정된 최종 등급으로 밀리등급 일치를 보이므로 그 일치가 보정이 낼 수 있는 오차의 상한을 함께 제한한다.

기기 등급은 계수율로 정의한다($m_{\rm inst} = 25 - 2.5\log_{10}(F_e / t_{\rm exp})$). 노출 시간에 영향받지 않는 정의다. 절대 보정(CMD 모드의 10단계)은 이 기기 등급에서 프레임별 영점과 필요 시 색항을 거쳐, Gaia DR3 \citep{gaia_dr3_2023} 참조별에 맞춘 절대 척도로 이어지며, 이때 천체측정·측광 품질 기준(RUWE 지수와 보정된 BP/RP 플럭스 초과 $C^*$; \citealt{riello2021})으로 걸러 낸다. 프레임 사이의 밝기 차와 대기 소광은, 대기질량과 얽혀 구분되지 않는 성분을 없애도록 프레임 오프셋 기저를 투영하여 분리한다.

### 2.5 모드별 분석

7단계를 지나면 두 모드로 나뉜다. CMD 모드에서는 PSF 측광(8단계)을 선택할 수 있다. 각 프레임의 밝고 외딴 별들로 `photutils`의 EPSF 기능을 써서 경험적 점퍼짐함수를 구성한 뒤 PSF 적합으로 다시 측광한다. 이 단계를 건너뛰면 이후 단계는 강제 구경 결과를 그대로 사용한다. 그다음 절대 보정(10단계), 색-등급도 작성(11단계), 이소크론 적합(12단계)이 이어진다. LC 모드에서는 대상별과 비교별을 선정하고(8단계), 차등 광도 곡선을 만들며(9단계), 여러 밤의 자료를 추세 제거하여 병합하고(10단계, SYSREM \citealt{tamuz2005}), 주기를 탐색한다(11단계, Lomb–Scargle과 위상 분산 최소화 \citealt{stellingwerf1978}).

본 연구의 검증 대상은 공용 과정이며, CMD 산출물은 3.12절에서 함께 다룬다. 이소크론 물리량 복원은 검증 범위에 넣지 않았고(5.2절), LC 모드의 주기 복원은 4절에서 사례로 제시한다.

### 2.6 사용자 작업 절차

각 단계 창은 그 단계에서 무엇을 정해야 하는지를 화면 안에서 설명한다. 23개 단계 창이
공통 안내 표를 참조하며, 안내문은 그 화면에서 내려야 하는 결정을 두세 줄로 적는다.
예를 들어 검출 단계는 검출 수가 너무 적을 때 검출 시그마를 낮추도록 안내하고, sky preview
단계는 FWHM과 하늘 배경 산포가 비정상일 때 파라미터를 조정하도록 알린다. 각 단계에서
사용자가 정하는 값과 그 값을 검증하는 절은 그림 1에 함께 표시하였다.

단계는 순서가 고정되어 있으며, 앞 단계가 끝나야 다음 단계가 열린다. 파이프라인 상태는
JSON으로 남으므로 프로그램을 닫았다가 열어도 진행한 지점에서 이어서 실행할 수 있다.
프레임 품질 검사를 통과하지 못한 프레임은 이후 단계에서 제외된다. 대상 좌표는 이름을
입력하면 SIMBAD 질의로 받아오며, 이후 WCS 계산과 카탈로그 조회가 그 좌표를 쓴다.
astrometric solution은 기본적으로 APEX의 내장 quad 솔버를 먼저 사용한다. ASTAP와
astrometry.net은 별도 사용자 옵션이며, 외부 탭을 선택했을 때만 실행된다. ASTAP
실행에서 fallback을 켠 경우에는 ASTAP 실패 뒤에만 astrometry.net을 시도한다.

### 2.7 재현성과 설정

실행 설정의 정본은 JSON workspace config이다. 대상·기기·검출·WCS·측광 설정을
하나의 파일에 기록하고, 기존 TOML 입력은 최초 로드에서 JSON으로 마이그레이션한다.
이후 실행은 JSON을 읽으며, `target.name`과 입출력 경로의 identity check로 서로 다른
대상의 설정이 섞이지 않게 한다. 각 단계의 파라미터, 입력·출력 경로, 실행 상태와
중간 산출물은 manifest에 남기고, 경로 함수가 정한 표준 위치를 사용한다. 따라서
결과 폴더만 보아도 처리 순서를 추적할 수 있고 중단한 지점에서 다시 실행할 수 있다.

중간 산출물(헤더 스캔, 검출, 측광)에는 signature와 스키마 버전을 붙였다. 그 값을
좌우하는 파라미터가 바뀌면 서명이 달라져 이전 결과가 자동으로 무효가 된다. 성능
비교 manifest에는 git commit, 패키지 버전, cache 상태, worker 수, BLAS 설정,
wall time과 peak RSS도 함께 기록한다. 이 구조 덕분에 파라미터·입력 프레임·코드
버전만으로 같은 계산을 재현할 수 있으며, 3절의 검증은 이 고정된 실행 기록을
기준으로 한다.

## 3. 검증

### 3.1 검증 방법과 자료

2절에서는 APEX가 raw 프레임을 보정하고, 천체를 검출해 WCS와 마스터 목록을 만든 다음,
고정된 위치에서 측광값을 얻어 CMD 또는 LC로 내보내는 순서를 설명하였다. 이 절은
그 순서를 그대로 따라간다. 검증은 (i) 위치·밝기·주기를 미리 정한 주입 참값 복원,
(ii) 같은 입력을 독립 구현에 넣은 결과 비교, (iii) 외부 목록 또는 운영 파이프라인과의
비교로 나누었다. 각 비교에서 영점·색항은 밝은 참조별에서 먼저 정하고 어두운 평가
구간은 그 뒤 고정했으므로, 결과에 맞춰 자유 파라미터를 다시 조정하지 않았다.

합성 영상은 고정 시드에서 포아송 광자잡음, 가우스 읽기잡음, 하늘 배경, 알려진 위치와
밝기의 별을 포함하도록 만들었다. 모든 시험은 GUI와 같은 Qt-free 계산 경로를 호출하고,
입력·설정·출력 signature를 manifest에 기록했다. 완전도 시험은 합성 영상만으로 실측
조건을 대신하지 않고 M67·NGC 6811·M13의 단일 노출 일곱 장에 경험적 PSF로 인공별을
주입하였다. 실측 측광 시험에는 NGC 6811, M5, M13을 사용했으며 PSF 측광의 기기 범위를
확인할 때 LCO QHY600과 Sinistro 자료를 추가하였다. 사용한 망원경·검출기·비닝·픽셀
스케일과 gain·읽기잡음·암전류는 부록 B에 정리하였다. 3.10절을 제외한 실측 측광은
대부분 Moravian C3-61000 자료에 의존한다는 점을 5.3절에서 한계로 명시한다.

표 2는 각 처리 요소와 검증 근거를 연결한다. 주입 참값이나 독립 구현과 직접 비교한 경우를 ‘직접’, 하류 산출물에서만 확인한 경우를 ‘간접’, 참값과 비교하지 못한 경우를 ‘미검증’으로 구분하였다. 이 분류는 구현 여부와 관계없이 이 논문이 제시하는 증거의 범위를 뜻한다.

### 3.2 검출기 보정 (Step 0)

검출기 보정에서는 먼저 실제 영상에서 보정의 크기를 확인하였다. 2026년 6월 11일 NGC 6811 관측의 bias 8장, 60초 dark 8장, $B$ flat 5장으로 마스터 프레임을 만들고, 같은 밤의 $B$ 60초 과학 영상에 차례로 적용하였다(그림 2). 마스터 flat은 시야 양끝 사이의 약 12% 감도 기울기를 보이며, flat 보정 전후 하늘 프로파일의 좌우 진폭은 12.9%에서 1.6%로 줄었다. 그림 2는 이 계산에 사용한 마스터 프레임과 같은 과학 영상의 단계별 변화를 함께 제시한다.

알려진 bias·dark·flat으로 만든 합성 프레임을 같은 코드로 보정했을 때, 복원 영상과 참 과학 영상 사이의 계통 오프셋은 $-0.004$ DN, 잔차 MAD는 $3.13$ DN이었다. 잔차 크기는 주입한 읽기잡음 3.0 DN과 비슷하다. 마스터 bias의 복원 RMS는 0.97 DN이었고, flat 모서리의 비네팅 잔차는 10.6 DN에서 0.7 DN으로 감소하였다. 선택적 L.A.Cosmic 우주선 제거 \citep{vandokkum2001}와 핫픽셀 보정은 주입한 우주선 화소의 100%와 핫픽셀의 94%를 제거했으며, 별 중심 오검출률은 0.000%, 구경 플럭스 변화는 0.00 mmag이었다.

gain, 읽기잡음, 암전류는 FITS 헤더값을 사용하지 않고 보정 노출에서 측정하였다(그림 3). 같은 flat 쌍의 광자전달관계 \citep{janesick2007}, bias 쌍의 차이, 노출시간별 dark 사다리를 APEX와 두 독립 경로로 각각 계산했다. APEX에서 gain은 $0.681\pm0.014$ e$^-$/ADU, 읽기잡음은 $2.35$ e$^-$, 암전류는 $0.0077$ e$^-$/s($R^2=0.998$)였고, Python `ccdproc`과 IRAF `ccdproc`도 각각 gain $0.681\pm0.014$ e$^-$/ADU, 읽기잡음 $2.35$ e$^-$, 암전류 $0.0077$ e$^-$/s를 냈다. 여기서 Python 경로는 Astropy 계열 패키지인 `ccdproc` 2.5.1 (\citet{ccdproc})이고, IRAF 경로는 IRAF `ccdred`의 `ccdproc` 태스크 (Tody 1986, 1993 \citep{tody1986,tody1993})이다. 두 이름은 같지만 같은 코드나 같은 패키지가 아니다. 이는 화소 배열이 같다는 뜻도 아니다. 이 카메라의 MaxIm/ASCOM \texttt{EGAIN} 키워드는 측정값보다 약 16배 작아 사용하지 않았으며, 그림 3의 상수만 3.7절의 오차 계산에 넣었다.

검출기 보정 산술의 비교는 저장소의 `calib_crosscheck_ngc6811.py`로 재현할 수 있다. Python 실행은 Python 3.12.3 환경의 `ccdproc` 2.5.1과 Astropy `CCDData`를 사용했다. FITS 화소 배열은 비교 조건을 맞추기 위해 APEX의 공통 `load_frame`으로 읽은 뒤 `CCDData(unit='adu')`로 감쌌으며, 이후의 결합·보정 연산만 Python `ccdproc`으로 수행했다. 마스터 bias는 `ccdproc.combine(method='median')`, dark는 bias를 뺀 뒤 같은 방식으로 결합했고, flat은 bias·dark를 차례로 보정하고 각 프레임을 중앙값 1로 정규화한 뒤 결합했다. 과학 영상에는 `subtract_bias`, `subtract_dark(scale=True)`, `flat_correct(norm_value=1.0)`를 순서대로 적용했다. APEX 쪽은 `apex.analysis.calibration`의 자체 float32 결합·보정 경로를 사용했다. IRAF 쪽은 WSL에서 PyRAF 2.2.3.dev9로 IRAF `ccdred` 태스크를 호출하여 `zerocombine`, `darkcombine`, `flatcombine`, `ccdproc`을 실행했다. 보존된 실행 로그에는 IRAF 배포판의 세부 버전이 남아 있지 않아 이를 임의로 특정하지 않았다. 세 경로 모두 이 비교에서는 오버스캔, trim, 우주선, 핫픽셀 보정을 껐다.

따라서 이 문헌의 `ccdproc` 인용은 패키지의 서지·사용법을 가리키며, Python과 IRAF의 동등성을 외부 논문이 입증했다는 뜻으로 읽지 않는다. 두 구현의 동등성 주장은 동일 raw 프레임에 대한 이 연구의 교차검증 결과로 한정한다. 그림 4에는 세 경로가 만든 master bias·dark·flat과 완전 보정 과학 영상의 **전체 프레임 중앙값 $\pm$ robust $\sigma$**를 단계별로 나란히 적었다. Python `ccdproc`의 실제 값은 bias $512\pm1.483$, 60초 dark $1\pm2.224$, flat $1\pm0.04428$, 완전 보정 영상 $633.5\pm31.39$ DN이고, APEX 열에도 같은 수치를 표시했다. IRAF `ccdproc`은 각각 $512\pm1.483$, $1\pm2.224$, $1.001\pm0.04431$, $633\pm31.37$ DN으로 기록된다. ‘일치’라는 말은 표시 정밀도까지 같은 수치를 뜻한다. 이 그림은 APEX에서 뺀 차이값이나 로그 막대를 보여 주는 그림이 아니다. 우주선과 핫픽셀 단계는 화소를 의도적으로 바꾸므로 이 표에서 제외하고 앞의 주입 시험으로 평가하였다.

마지막으로 LCO의 QHY600 CMOS와 4증폭기 Sinistro CCD raw 프레임을 APEX로 보정한 뒤 BANZAI 산출물 \citep{mccully2018}과 비교하였다(그림 5). QHY600의 차이는 프레임 전체에서 거의 균일한 $+0.06$ e$^-$였고, Sinistro는 하늘과 천체 구조가 약 0.3% 범위에서 일치했지만 차영상에 증폭기 사분면 구조가 남았다. 이 결과는 bias·dark·flat 연산이 두 검출기에서도 재현됨을 보이는 한편, 증폭기별 gain·오버스캔·크로스토크 조립은 기기별 처리가 필요함을 보여 준다. APEX의 현재 보정 범위는 단일 CCD 또는 조립이 끝난 영상이다.

### 3.3 프레임 품질 관리

프레임 QC는 등급을 보고 영상을 거르는 단계가 아니다. 0단계 보정과 1–3단계의 파일·영역 정리가 끝나면 4단계 검출기가 각 프레임에서 천체 목록과 진단 통계를 반환하고, 그 직후 evaluate_frame_qc가 그 통계만으로 PASS, REVIEW, FAIL을 붙인다. 이 논문에서 사용한 SEP 경로에서는 밝은 천체 최대 25개의 방사형 프로파일에서 얻은 FWHM의 중앙값, SEP Background가 반환한 전역 하늘 중앙값과 RMS, 검출 수·늘어남·포화 수·품질 점수를 기록한다. 같은 필터 묶음 안에서 각 지표의 중앙값과 MAD로 robust $z$를 만들고, 시상 모형과의 FWHM 비, 검출 수의 부족·과다, 하늘 잡음의 예상값 대비 비율을 함께 계산한다. 예상 하늘 잡음은 측정 하늘과 gain, 읽기잡음으로 $\sigma_{\mathrm{sky,exp}}=\sqrt{B g+\mathrm{RN}^2}$로 구한다. 이 결과는 WCS(5단계), 마스터 목록(6단계), 강제 측광(7단계)으로 넘기기 전에 나쁜 프레임을 보류하거나 검토하게 한다.

판정 문턱은 정상 묶음에서 $|z|=3.0$ (FWHM·하늘·검출 수) 또는 하늘 잡음 비 2.5를 넘으면 REVIEW, 각각 4.5와 6.0을 넘으면 FAIL로 두었다. FWHM 모형 비는 1.30/1.60, 늘어남은 1.22/1.35를 review/fail 경계로 사용하며, 포화율·최소 천체 수·품질 점수도 같은 판정에 포함한다. 그림 6의 합성 하룻밤은 깨끗한 영상 24장과 네 종류의 결함 영상(각 5장)으로 구성했다. 기본 문턱값에서 깨끗한 24장은 모두 PASS, FWHM을 1.8배 넓힌 5장은 모두 FAIL, 하늘을 5배 밝힌 5장과 실제 읽기잡음을 25 e$^-$로 높인 5장은 모두 REVIEW였다.

그림 6에 적은 depth cost (mag)는 별에서 측정한 등급이 아니다. 코드가 각 필터의 밤 중앙값을 기준으로 $\sigma_{\mathrm{sky,e}}\,\mathrm{FWHM}$의 증가를 $2.5\log_{10}$으로 바꾼 **예상 검출 한계 손실**이며, 깊이 문턱(0.5/1.5등급)을 정하는 보조 지표다. 실제 기기 등급은 그 뒤 7단계 강제 측광에서 계수율로 $m_{\mathrm{inst}}=25-2.5\log_{10}(F_e/t_{\mathrm{exp}})$를 계산하고, 10단계에서 영점과 색항을 적용할 때 처음 생긴다. 따라서 QC의 depth cost를 측광 등급으로 읽을 수 없다.

균일한 투과율만 0.7등급 낮춘 5장은 PASS였다. 이 변화는 PSF 모양·하늘 중앙값·RMS·검출 수를 거의 보존하여 영상 통계만으로 식별되지 않는 의도된 사각지대다. 그런 프레임은 7단계 뒤 교차매칭한 비교별의 프레임별 영점 또는 플럭스 오프셋으로 다시 검사해야 한다. 이 순서를 분리해 두었기 때문에, 다음 3.4절에서는 먼저 검출 문턱값이 만드는 헛검출 오염을 고정하고, 3.5절에서 그 문턱값 아래의 검출 완전도를 측정한다.
### 3.4 검출 문턱과 헛검출 오염

검출 완전도를 해석하려면 먼저 문턱값이 만드는 오염을 정해야 한다. 합성 영상의 문턱값 훑기에서는 $2$–$6\sigma$ 사이에서 $m_{50}$이 1.04등급 변했지만, 고르고 별이 성긴 배경에서는 시행 30회당 헛검출이 1–2개뿐이었다. 실측 영상의 밝은 별 날개와 배경 구조를 포함한 오염률은 부호반전 시험으로 별도로 측정하였다.

배경을 뺀 잡음의 부호가 대체로 대칭이라는 성질을 이용해, 원 영상과 부호를 뒤집은 영상에 같은 검출기를 적용하였다 \citep{serra2012, serra2015, molino2014}. 부호반전 영상의 양의 검출 수 $N_-$를 잡음 기원의 헛검출로 보고 순도를 $(N_+-N_-)/N_+$로 추정하였다. M13, M3, M67, NGC 6811의 실제 프레임 다섯 장에서 기본값 $3.2\sigma$의 추정 오염률은 모두 2% 이하였다(그림 7-a). Gaia DR3와의 대조에서도 추정 헛검출 수는 네 자릿수 범위에 걸쳐 2배 이내였고, 검출 수가 가장 많은 구간의 오염률은 2.4%였다(그림 7-b).

각 프레임에서 오염률 5%를 넘지 않는 최소 문턱값은 $1.5$–$2.2\sigma$로 달랐다. $1.2\sigma$에서는 한 프레임의 검출 4,066개 가운데 1,341개가 부호반전 영상에서도 나타났다. 따라서 고정 문턱값의 안전 여유는 프레임마다 같지 않다. 이 방법은 잡음 대칭성에 기대므로 우주선, 핫픽셀, 인공위성 궤적처럼 양의 방향으로만 생기는 결함은 세지 못한다. 또한 다섯 프레임은 모두 같은 카메라에서 얻었으므로, 여기서 측정한 하한을 다른 기기의 권고값으로 사용하지 않았다.

### 3.5 검출 완전도

오염 수준을 먼저 고정한 뒤, 검출 완전도는 M67, NGC 6811, M13의 실측 단일 노출 일곱 장에 프레임당 인공별 3,000개를 주입해 측정하였다(그림 8). 배경 잡음은 5–58 e$^-$/px, FWHM은 5.2–9.0 px 범위를 덮는다. 각 별은 해당 프레임에서 만든 경험적 PSF로 주입했으며, 기존 천체와 겹친 별은 제외하고 실제 과학 처리와 같은 SEP 검출 경로 \citep{barbary2016}를 적용하였다. 등급 구간별 회수율과 Wilson 95% 이항구간을 계산하고, 회수율이 0.5를 지나는 지점을 $m_{50}$으로 정하였다.

대표 세 프레임의 $m_{50}$은 17.65, 15.64, 14.90등급이었다(그림 8-a). 같은 검출 설정을 썼어도 하늘 밝기와 시상이 달라지면 등급으로 표현한 깊이가 달라진다. 각 주입별을 기대 peak-pixel S/N으로 다시 나타내면 일곱 곡선의 전이 위치는 $\mathrm{S/N}_{50}=4.05\pm0.18$에 모였고, 합동 오차함수 적합은 4.0을 주었다(그림 8-b). 다만 프레임별 차이가 완전히 사라지는 것은 아니다. 최소 연결 면적 조건 때문에 FWHM 5.2–5.3 px 프레임의 $\mathrm{S/N}_{50}$은 4.2–4.3, FWHM 7–9 px 프레임은 3.8–3.9였으며, 프레임별 값과 FWHM의 Spearman 계수는 $-0.94$였다. 따라서 S/N은 등급보다 조건 차이를 잘 줄여 주지만, PSF 폭에 따른 잔차까지 없애는 보편 상수로 해석하지 않았다.

이 완전도 곡선을 한 실측 프레임의 마스터 목록에 적용해 예상한 검출 수는 실제 검출 수와 6% 이내에서 일치하였다. 이 결과가 지지하는 범위는 시험한 배경, 시상, 천체 밀도 안에서의 단일 노출 검출 확률이다.

### 3.6 WCS 엔진 비교

기본 경로는 외부 프로그램과 인덱스 없이 실행되는 APEX 내장 quad 솔버이다. ASTAP
\citep{astap}과 astrometry.net \citep{lang2010}은 별도 사용자 옵션으로 두었으며,
외부 탭을 선택했을 때만 실행된다. M13의 $B,R,V$ 단일 노출 여덟 장을 엔진별 사본으로
나누고 같은 4단계 검출 목록을 입력하여, 각 해를 독립 FITS 헤더에 저장하였다. 세 엔진은
공통 Gaia DR3 교차매칭·정제·수용 게이트를 거쳤다.

정제 전 각 헤더 WCS를 독립적으로 투영한 결과는 그림 9에 보였다. 같은 2″ 최근접
매칭으로 계산한 프레임별 중앙값은 내장 0.77 px, astrometry.net 0.93 px, ASTAP
1.10 px였다. 이 그림의 잔차는 솔버 비교용으로 공통 정제를 적용하지 않은 값이며,
내장 솔버가 해를 구할 때 사용한 검출–Gaia 쌍과 같은 종류의 쌍으로 평가된다는 한계가
있다. 따라서 그림 9와 표 4의 수치는 서로 다른 질문, 즉 헤더 해의 독립 비교와
공통 정제 뒤의 운영 결과를 각각 나타낸다.

표 4에 보인 수치는 공통 Gaia 정제 뒤의 잔차와 벽시계 시간이다. 내장 솔버는 중앙 잔차가
0.346 px(0.137″), ASTAP은 0.493 px(0.195″), astrometry.net은 0.493 px(0.195″)였다.
내장 솔버와 ASTAP은 여덟 장 모두 수용되었고, astrometry.net은 일곱 장이 수용되었다.
프레임당 실행시간 중앙값은 각각 11.1 s, 3.1 s, 150.8 s였다. 따라서 이 자료에서는
내장 솔버가 잔차는 가장 작았지만 ASTAP보다 빠르다고 말할 수 없다. 내장 경로를 기본으로
둔 이유는 속도를 최우선 기준으로 두지 않고, 별도 실행 파일·인덱스·WSL 또는 네트워크
없이 raw 입력과 동일한 설정에서 재현 가능한 기준 해를 제공하기 위해서다.

이어진다.

### 3.7 측광 오차 모형

3.6절에서 위치(WCS)를 독립적으로 확인했으므로, 여기서는 그 위치에서 얻은 플럭스와 보고 오차의 전파를 검증한다. $m=14.5$–20.0의 합성별을 주입해 실제 측정 오차와 파이프라인이 보고한 오차를 비교하였다(그림 10). 평균 등급 편향은 $m=17.0$까지 5 mmag 이하였으며, 더 어두운 구간에서는 플럭스가 0에 가까울 때의 비선형 등급 변환과 검출 선택의 영향이 커졌다. 구간별 경험 RMS는 CCD 관계식 $\sigma_m=1.0857/\mathrm{SNR}$을 1.9 dex에 걸쳐 따랐다.

S/N이 5보다 큰 3,404개 측정의 pull $(m_{\rm meas}-m_{\rm true})/\sigma_m$은 평균 $-0.148$, 표준편차 1.014였다. 보고 오차와 경험 RMS의 중앙비는 0.976이었고, 가장 큰 부족은 $m=19.0$에서 17%였다. $m=20.0$에서는 양의 플럭스로 측정된 별만 남는 선택효과가 커지므로 가장 어두운 두 점을 단조 추세로 해석하지 않았다. 이 시험은 주어진 잡음 모형의 전파를 검증하며, 실제 영상에서의 일치도는 3.9절의 독립 엔진 대조로 확인한다.

### 3.8 파라미터와 관측 조건에 대한 민감도

구경 배율, 하늘 밝기, 시상을 한 번에 하나씩 바꾸어 결과가 얼마나 움직이는지 측정하였다(그림 11). 각 점은 30회 시행에 시행당 40개의 인공별을 넣은 1,200개 측정으로 이루어지며, 경험적 PSF 주입부터 4단계 검출과 강제 구경 측광까지 생산 코드 경로를 거친다. 오차막대는 시행 단위 클러스터 부트스트랩의 95% 구간이다.

FWHM 6.0 px의 고정 프레임에서 구경 반지름을 바꾸면 등급 오차 MAD는 $0.80\times$FWHM에서 0.051등급으로 가장 작았고, $2.5\times$FWHM에서 0.181등급이었다(그림 11-a). 생산 설정의 최소 반지름은 4 px이므로 $0.5\times$FWHM 요청은 4 px로 제한되며, 그림에서는 열린 표식으로 구분하였다. 위치 RMSE의 중앙값은 0.255 px였고 구경 배율에 따라 변하지 않았다. 위치는 검출 단계에서 정해져 측광 구경을 사용하지 않기 때문이다.

하늘 배경을 50에서 1,000 ADU로 높이면 $m_{50}$은 18.38에서 17.06등급으로 줄고 등급 오차 MAD는 36에서 88 mmag으로 늘었다(그림 11-b). FWHM을 3.0에서 6.0 px로 넓히면 $m_{50}$은 18.07에서 16.96등급, MAD는 42에서 60 mmag으로 변했다(그림 11-c). 문턱값 동반 훑기에서는 $2.0\sigma$와 $6.0\sigma$ 사이에 $m_{50}$이 18.36에서 17.32등급으로 1.04등급 변하였다. 합성 장의 낮은 오염률은 실측 자료에 그대로 적용하지 않았으며, 문턱값의 실제 비용은 3.4절의 부호반전 시험으로 평가하였다.

### 3.10 PSF 측광

CMD 모드의 PSF 측광은 프레임마다 밝고 고립된 별로 EPSF를 만들고, 4단계에서 정한 위치에서 플럭스를 다시 적합한다. 이 절은 PSF 측광과 강제 구경측광의 별 단위 차이 $\Delta=m_{\rm PSF}-m_{\rm ap}$를 비교한다(그림 13). 두 쪽 모두 S/N $>20$이고 혼잡 또는 포화 플래그가 없는 별만 사용했으며, EPSF 정규화와 구경보정의 상수 차이를 없애기 위해 프레임별 중앙값을 뺐다. 따라서 이 시험은 두 내부 측정법의 일치도를 평가하며 PSF 경로의 독립적인 절대 정확도 시험은 아니다.

Moravian C3-61000, LCO QHY600, LCO Sinistro의 세 카메라와 여섯 자료군, 단일 노출 67장에서 90,201개 별을 비교하였다. 자료군별 잔차 MAD는 7–40 mmag이었다(그림 13-a). M67은 7 mmag, M13은 40 mmag이었으며, $|\Delta|>0.2$등급인 별의 비율은 성긴 장에서 0.8–2.3%, M13에서 8.9%, 은하가 포함된 NGC 5985 장에서 12.9%였다. 혼잡과 구조화된 배경이 두 측정법의 차이를 키우는 방향과 일치한다.

M45의 $2.0^\circ\times1.3^\circ$ 시야 19장에서는 마지막 모서리 구간을 제외한 반경별 중앙값의 폭이 14 mmag이었다(그림 13-b). 안쪽과 바깥쪽의 중앙값 차이는 4 mmag이었고, 마지막 모서리 구간만 $+28$ mmag를 보였다. 한 프레임에 EPSF 하나를 쓰는 현재 설정은 시야 대부분에서 이 자료의 별 단위 산포보다 작은 위치 의존성을 남겼지만, 모서리 보정은 추가 검토가 필요하다.

이 검증 과정에서 우주선 단일 화소가 EPSF 참조별로 선택되는 문제와 카메라별 형태 컷이 Sinistro 참조별을 하나까지 줄이는 문제가 확인되었다. 전자는 우주선 제거를 기본으로 켜고 FWHM 및 대칭성 조건을 추가해 막았으며, 후자는 후보가 너무 적을 때 형태 컷을 단계적으로 완화해 59개를 확보하도록 수정하였다. 그림 13의 값은 수정 뒤 현재 코드로 다시 계산한 결과다.

### 3.11 두 구상성단의 밀집 영역 측광 비교

밀집 영역에서는 M5와 M13의 실제 중심부에서 구경측광과 PSF 측광의 차이를 최근접 이웃 거리로 비교하였다(그림 14). APEX의 밀도 정점 기준으로 중심부의 천체 밀도는 바탕보다 M5에서 34배, M13에서 30배 높았으며, 같은 지표로 계산한 NGC 6811의 11배보다 컸다. M5의 683개, M13의 482개 별에서 밝고 고립된 별로 영점만 맞춘 뒤 $m_{\rm ap}-m_{\rm PSF}$를 계산하였다.

두 성단 모두 약 10 px의 분해 하한부터 수백 px까지 구간 중앙값이 0 부근에 있었고, 각 중앙값은 0에서 0.04등급 이내였다. 이 결과는 시험한 지상 $2\times2$ 비닝 자료가 분해하는 범위에서 두 측광법 사이에 최근접별 거리에 따른 추가 편향을 찾지 못했다는 뜻이다. 두 방법이 같은 APEX 검출 목록을 공유하므로 외부 절대 정확도는 판단할 수 없으며, 약 10 px($\sim4$″)보다 가까운 미분해 겹침도 시험하지 못했다. 그림 14는 이 두 제한을 포함한 내부 일관성 결과다.

### 3.12 외부 목록과 CMD 재현

NGC 6811의 APEX 측정과 Gaia 변환 기준을 Gaia와 독립인 PS1 \citep{chambers2016}에 각각 비교하였다(그림 15-a,b). 1,928개 교차매칭 별에서 밝은 구간 14.5–15.5등급을 0으로 맞춘 뒤 어두운 쪽 변화를 계산하였다. $B$에서 APEX–PS1 변화는 $+0.010$등급, Gaia 변환 기준–PS1 변화는 $+0.022$등급이었다. $V$에서는 각각 $+0.024$, $+0.007$등급이었다. 밴드에 따라 더 큰 잔차가 나타나는 쪽이 바뀌므로, 어두운 쪽 오차를 APEX 한쪽에만 돌릴 수 없다.

$B$의 Gaia 변환값은 BP 광도에 의존한다. Gaia BP는 어둡고 푸른 천체에서 배경 추정의 영향을 받는 것으로 알려져 있으며 \citep{riello2021}, 여기서도 $B$의 어두운 쪽 변화가 APEX보다 Gaia 변환 기준에서 더 컸다. 이 결과는 밝은 별로 정한 Gaia 영점의 사용을 배제하지 않지만, 어두운 구간의 검증에는 PS1이나 Gaia $G$ 기반 기준을 함께 보아야 함을 시사한다. $V$에서는 APEX 쪽에 0.024등급의 작은 잔차가 남아 있어 측정과 참조의 계통을 밴드별로 따로 보고하였다.

같은 자료의 최종 산출물도 확인하였다. APEX와 Gaia 변환값이 모두 유효한 1,917개 별로 Johnson $V$ 대 $B-V$ CMD를 만들면, 시그마 클리핑한 주계열 ridgeline 사이의 RMS는 18.7 mmag이었다(그림 15-c). 이 비교는 보정된 CMD의 위치와 형태를 평가한다. 나이, 금속함량, 거리, 적색화를 CMD에서 복원하는 등시선 적합은 별도의 축퇴 문제이므로 검증 범위에 넣지 않았다(5.2절).

### 3.13 시계열 분석 모듈 (SYSREM·PDM)

PDM과 SYSREM \citep{tamuz2005}은 APEX가 자체 구현한 LC 모듈이다. 두 모듈의 목적은
표준 구현과의 우열을 겨루는 데 있지 않다. APEX의 결측값·오차 가중치·대상 신호 보존
계약이 실제 계산에 반영되는지를 독립 경로와 주입 자료로 시험하였다.

먼저 YZ Boo 관측과 같은 표본 배치(두 밤, 364점)를 사용하여 PDM의 최소값을 독립
`pyPDM` 구현과 비교하였다. 검색 범위는 0.05–0.30일이며, APEX의 최적 주기는
0.104295일, `pyPDM`은 0.104020일로 차이는 $2.8\times10^{-4}$일이었다. 10개 bin에
세 cover를 적용한 최소값은 `pyPDM` 0.104220일, APEX 0.104295일로 차이가
$8\times10^{-5}$일이었다. 두 설정에서 theta 곡선의 Pearson 상관은 각각 0.996과
0.997이었다. 문헌 주기 0.104092일
\citep{yang2018}은 두 구현의 최소값 주변에 있었다. 이 시험은 계산식과 표본 처리의
일치를 보인 것이며, 두 밤의 alias를 해결했다는 뜻은 아니다.

SYSREM은 \citet{tamuz2005}의 갱신식과 APEX의 결측값·오차 가중치를 같은
행렬에 적용하여 비교하였다. 원래 PySysRem 패키지는 Python 2와 고정 파일 입출력을
요구해 현재 환경에서 실행 가능한 비교 경로로 사용할 수 없었으므로, 저장소의
`sysrem.py` 갱신식(73–101행)을 독립 검산 코드로 옮겨 동일한 241별×124프레임 행렬에
적용했다. 네 개의 강한 성분에서 APEX와 독립 구현의 성분 상관은 각각
$|r|=0.890, 0.729, 0.584, 0.074$였고, 다섯 번째 약한 성분은 $|r|=0.132$였다.
밝은 비교별의 잔차 차이는 RMS 14.9 mmag였다. 강한 성분의 순서와 크기는 일치했지만
약한 성분은 성분 회전과 초기화에 민감했다. 따라서 APEX의 SYSREM 검증은 지배 계통
성분과 대상 신호 보존에 한정하고, 반복 횟수 5를 모든 관측에 최적이라고 해석하지 않는다.
실제 적용에서는 비교성 산포 감소와 변광 대상의 진폭·주기 보존을 함께 보고한다.

그림 16은 위의 독립 비교와 별도로, 생산 LC 진입점을 통한 합성 주입 시험을 보여 준다.
4절과 같은 하룻밤 배치(5.2시간, 80점)에 주기 0.06–0.20일과 잡음 5–40 mmag를
조합하고 12회씩, 모두 288개 시계열을 분석하였다. 잡음 20 mmag 이하에서 PDM 주기
오차 중앙값은 1.4%였고, 주기 0.20일·잡음 40 mmag에서 최대 오차는 6.8%였다.
같은 계열의 Lomb–Scargle 결과와 비교하면 차이는 관측 기선이 한 주기를 겨우 포함하는
0.16–0.22일 구간에 모였다. 별 60개·프레임 120장의 별도 SYSREM 주입에서는 비교성만
사용할 때 대상 진폭이 109% 남았고, 대상을 성분 추출에 포함하면 0.4%만 남았다.
이 패널은 주입 조건에서의 신호 보존을 확인하며, 241×124 실측 크기 행렬의 독립
갱신식 비교와는 다른 검증 자료다.

## 4. 과학 적용: 변광성 광도 곡선

3절은 측정 단계별 정확도를 평가하였다. 이 절에서는 그 결과가 최종 과학 산출물까지 이어지는지 확인한다. 고진폭 $\delta$ Scuti 별 YZ Boötis(문헌 주기 $P = 0.104092$ 일, $V$ 진폭 pk-pk $\simeq 0.42$ 등급; \citealt{yang2018})를 raw 프레임에서 주기까지 APEX LC 모드의 그래픽 작업흐름으로 줄였다. 이 사례에서는 별도 스크립트를 사용하지 않았다.

2026-03-28의 $r$ 밴드 하룻밤 자료(5.2시간, 차등측광 80점)를 문헌 주기로 접으면 출판된 톱니 곡선이 재현되고(그림 17-a), 진폭은 pk-pk $0.392$ 등급이다. 목록의 $V$ 값보다 작은 $r$ 밴드 진폭은 파장에 따른 맥동 진폭 차이와 일치한다. $\delta$ Scuti 별의 맥동 진폭은 파장이 길수록 작아지므로, 이 차이는 예상되는 방향이다. 답을 가정하지 않고 맹검으로 돌린 Lomb–Scargle 주기도 \citep{vanderplas2018}에서 이 밤의 최고 봉우리는 $P = 0.10464$ 일로, 문헌값과 $0.5$%(47초) 차이다. 이 밤은 맥동 주기 2.1회분밖에 담지 못하므로 짧은 기선(baseline) 추정이며, 출판된 ephemeris를 개선한 값으로 제시하지 않는다. APEX의 그래픽 작업흐름만으로 raw 프레임에서 문헌값과 일치하는 주기와 진폭을 얻었다.

하루 간격의 두 밤 자료를 결합하면 최대 파워를 갖는 주기가 $0.0946$ 일로 이동하고, 문헌 주기 $0.10409$ 일은 부봉우리로 남는다. 두 주기는 1 cycle d$^{-1}$ alias 관계에 있으며, 이는 단일 관측지의 관측 창(spectral window)에서 발생한다. 따라서 APEX는 후보 주기를 제시하지만 alias를 자동으로 판별하지 않는다. 프레임 품질 게이트(3.3절)도 같은 방식으로, 예측보다 얕은 프레임을 표시하되 채택 여부는 사용자가 결정한다.

이중 모드 별 AE Ursae Majoris \citep{zhou2001, paparo2001} 는 앞으로의 과제로 적어 둔다. 기본 모드와 첫 배진동 모드를 가르려면 아직 APEX에 없는 prewhitening이 필요하고, 단일 관측지 alias 탓에 최고 봉우리가 그런 별의 참 기본 주기를 못 미덥게 가리키기 때문이다.

## 5. 논의

### 5.1 검증 결과의 범위

3.2–3.13절은 raw Step 0에서 CMD·LC의 중간 산출물까지 이어지는 각 고리를 따로 확인하였다. 검출기 보정은 주입 참값과 Python `ccdproc`, IRAF `ccdproc`, BANZAI를 서로 다른 기준으로 대조했고(3.2절), 프레임 QC·검출 문턱값·완전도는 결함 주입과 인공별 회수로 시험했다(3.3–3.5절). WCS는 세 엔진의 Gaia 잔차와 수용률을 함께 기록했고(3.6절), 측광 오차는 pull 표준편차 1.014와 독립 측광 잔차로 확인했다(3.7, 3.9절). PSF, 혼잡한 장, 외부 목록 비교는 이 공용 목록이 CMD까지 전달되는지를 확인하며(3.10–3.12절), PDM·SYSREM은 LC 모듈의 독립 계산과 신호 보존을 시험했다(3.13절).

이 결과는 시험한 자료와 관측 조건에서 GUI가 호출하는 계산 경로가 독립 기준과
수치상 일관됨을 보인다. 그러나 이는 모든 기기·하늘 배경·혼잡도에서의 정확도 보증이
아니다. 강한 공간 배경, 분해 한계 이하의 겹침, 외부 prior 없는 등시선 물리량 복원,
그리고 검증에 포함하지 않은 기기의 절대 보정은 범위 밖이다.

### 5.2 등시선 적합 결과의 범위

측광 정확도와 CMD에서 나이·금속함량·거리·적색화를 추정하는 일은 서로 다른
검증 문제다. 이를 분리해 보이기 위해 M67의 $gri$ 측광을 같은 PARSEC 계열
등시선에 맞추고, APEX의 간단한 격자 적합을 ASteCA \citep{perren2015}와 비교하였다.
두 경로는 비슷한 거리 모듈러스를 주었지만 나이·금속함량·적색화는 달랐다.

| 적합 경로 | 나이 (Gyr) | [M/H] | $E(B-V)$ | $(m-M)_0$ |
|---|---:|---:|---:|---:|
| APEX 격자 적합 | 2.80 | −0.502 | 0.174 | 9.633 |
| ASteCA | 3.20 | −0.246 | 0.097 | 9.634 |
| 문헌 범위 | 약 4 | 약 0 | 약 0.04 | 약 9.7 |

**표 5.** 동일한 $gri$ 자료에 대한 예시적 등시선 적합. 두 구현의 결과가 다르다는
사실은 측광 단계의 실패를 뜻하지 않으며, 제한된 밴드와 영점·색항·소광 사이의 축퇴를
보여 준다.

표준성 또는 외부 prior를 명시한 별도 시험에서는 전 밴드 영점을 같은 표준계에 맞추는
조건이 $U-B$ 축퇴를 줄였다. 다만 이 경우 prior와 영점 앵커의 출처가 결과의 일부가
되므로, 이를 넣은 적합을 외부 prior 없는 자동 복원으로 부르지 않는다.

밝은 별 5%를 제외했을 때 ASteCA의 적합 나이는 2.60 Gyr로 이동하였다. 따라서
이 절의 수치는 APEX가 자동으로 문헌 물리량을 회복한다는 증거가 아니다. 외부 prior와
더 넓은 색 범위를 넣으면 축퇴를 줄일 수 있지만, 그 prior와 밴드 선택 자체가 결과의
일부가 된다. 본 논문에서 검증한 주장은 raw 프레임에서 재현 가능한 측광과 CMD 산출물의
생성까지이며, 등시선 물리량은 후속 연구에서 독립 자료와 함께 검증할 대상으로 남긴다.

PSF 측광은 카메라 세 대에서 구경 측광과 별 단위로 견주었지만(3.10절), PSF 경로
자체에 대한 주입 참값 시험은 두지 않았다. 소광 estimator는 합성 자료에서만 알려진
계수를 복원했고, 마스터 목록의 교차프레임 매칭도 주입 참값 대비 순도·완전도로 채점하지
않았다(표 2). 이 항목들은 공용 raw→CMD/LC 흐름의 다음 검증 대상으로 남긴다.

### 5.3 일반성의 한계

**측광의 기기 폭.** 측광 확인 가운데 3.3·3.9·3.11·3.12절에 쓴 실측 자료는 모두 같은 카메라에서 나왔다. 독립성은 성단 종류보다 교차 확인의 *방법들*(SEP, IRAF/DAOPHOT, Gaia, Pan-STARRS 1)에서 확보했다. 기기 축이 더해진 곳은 둘이다. *보정*은 카메라 두 대를 더해 독립 파이프라인과 대조했고(3.2절), *PSF 측광*은 카메라 세 대·자료 여섯 벌에서 구경 측광과의 일치를 확인했다(3.10절). 남은 시험은 다른 망원경·카메라를 절대 보정과 외부 목록 대조까지 통과시키는 것이다.

**구조가 뚜렷한 하늘 배경.** APEX는 하늘 배경을 시그마 클리핑한 고리에서 추정하는데, 이는 배경이 구경과 고리 규모에서 국소적으로 고르다는 가정을 깐다. 빈 하늘의 별에는 맞고, 여기 쓴 성단 장처럼 매끄럽고 천천히 변하는 배경에도 무리 없다. 완만한 기울기는 고리 중앙값이 대체로 흡수하기 때문이다. 그러나 배경이 구경 규모에서 구조를 지니면(밝은 성운 방출, 은하수 권운, 또는 분해된 은하 빛 위에 겹친 별) 이 가정이 깨진다. 그런 곳에서는 고리가 천체 밑의 참 배경을 잘못 추정해 측광이 위치에 따라 치우친다. 이 영역은 여기서 쓰지도 검증하지도 않았고, 3.11절의 항성 밀집(천체 혼동)과는 다른 축, 곧 퍼진 배경의 문제다. 숙주 은하나 강한 성운 방출 속에 파묻힌 변광성·순간천체의 측광은 공간적으로 분해된 배경 모형화나 템플릿 차감을 필요로 하는데(AutoPhOT가 은하 속 순간천체에 하는 방식; \citealt{brennan2022}), APEX는 아직 그렇게 하지 않는다. 4절의 변광성 대상은 비교적 깨끗한 장의 은하계 맥동 별이므로, 이 한계는 여기 보고한 결과에는 영향을 주지 않는다.

**분해 한계 아래의 밀집.** 3.11절은 이 지상 $2\times2$ 비닝 자료가 분해하는 $\sim$10 px($\sim$4$''$) 거리까지는 밀집도에 따른 편향을 찾지 못한다. 우주 기반이나 lucky imaging이라면 살필, 그보다 미세한 겹침은 시험하지 못한 채로 남으며, 바로 그곳이 구경 측광이 동시 PSF 맞추기에 견줘 여전히 나빠질 것으로 예상되는 대목이다.

**외부 교차매칭 실패와 측광 결과의 구분.** M13의 보관된(옛 파이프라인의) Gaia 교차매칭은 절대 보정에 사실상 못 쓴다(검출된 1347개 중 38개만 실시간 Gaia DR3 조회에서 살아난다). 3.11절의 내부적·Gaia 무관 구경-대-PSF 시험에는 이 자료를 사용할 수 있었다. 강제 측광은 마스터 목록의 화소 위치를 사용하므로 Gaia 식별자 없이도 수행된다.

### 5.4 적용 지침

구경 배율은 기본값 $0.8\times$FWHM을 그대로 쓴다. 실측 산포 최소점이 그 자리에 있고(3.8절), 시상이 5 px보다 좋은 프레임에서는 4 px 하한이 대신 걸린다. 프레임 QC는 두 단계로 본다. 영상 수준 점검(3.3절에서 검증)은 회색 투과율 손실을 잡지 못하므로, 그 고장 유형에는 측광 수준(교차매칭한 별 플럭스) 점검이 필요하다. 어두운 쪽 측광 *검증*에는(영점 매기기가 아니라) BP 변환 Gaia 등급보다 $G$ 기반이나 Pan-STARRS 참조를 쓴다(3.12절). 붐비는 장에서는 Gaia에 교차매칭한 보정별 통계보다 내부 구경-대-PSF 진단을 앞세운다. Gaia 자체의 품질 기준이 최악의 겹침을 세기도 전에 걸러 내기 때문이다(3.11절). 성운기가 강하거나 분해된 은하 빛이 있는 장에서는 국소 배경 모형화나 템플릿 차감을 쓴다. 고리 하늘 배경 추정은 항성 장을 겨냥한 것이다(5.3절).

## 6. 결론

APEX의 목적은 새로운 검출기 보정식이나 단일 분석 알고리즘을 제안하는 데 있지 않다.
APEX는 raw 영상에서 시작해 검출기 보정, 프레임 QC, 천체 검출, WCS, 공용 마스터 목록,
강제 구경·PSF 측광을 거쳐 CMD 또는 LC를 한 소프트웨어 안에서 생성하는 실행 가능한
경로를 제공하는 것이다. GUI는 각 단계의 선택과 중간 산출물을 보여 주고, 같은 계산부는
헤드리스 실행과 manifest 기록을 지원하므로 사용자가 어느 단계에서 무엇을 바꾸었는지
추적할 수 있다.

이 논문은 그 흐름의 연결부를 수치로 점검하였다. 검출기 보정은 독립 구현과 카메라간
자료에 대해 일치했고, 주입 영상의 검출·측광 오차는 알려진 참값을 회복했으며, WCS는
내장 기본 경로와 사용자가 선택하는 외부 엔진의 잔차·시간·수용률을 함께 제시했다.
CMD 경로는 Gaia·PS1과 대조했고, LC 경로는 독립 PDM·SYSREM 계산과 YZ Boo 예제로
raw에서 주기까지 이어졌다. 이 결과는 시험한 자료 범위에서 APEX의 공용 경로가 독립
기준과 일관됨을 뒷받침한다.

반면 구조화된 공간 배경, 분해 한계 이하의 혼합, 더 넓은 기기의 절대 보정, 외부 prior
없는 등시선 물리량의 자동 복원은 이 논문의 결론에 포함하지 않았다. 따라서 APEX의
기여는 특정 기능의 최초성보다, 표준 라이브러리와 APEX 고유 모듈을 명시적으로 구분하고
raw→CMD/LC 전체 흐름을 재현 가능하게 묶은 뒤 그 연결부를 검증했다는 데 있다.

## 부록 A. 용어 대조표

APEX를 처음 쓰는 독자는 대개 IRAF/DAOPHOT이나 파이썬 측광 패키지 가운데 하나에
익숙하다. 아래 표는 같은 개념을 세 환경에서 각각 무엇이라 부르는지 대응시킨 것이다.

그림 4는 두 독립 구현을 모두 사용한 단계별 절대 산출값 표이며, IRAF 태스크명과
PyRAF 실행 환경은 확인한 것만 적었다.

기록한다. 제조사 사양은 표의 인용을 따르고, gain·읽기잡음·암전류는 그림 3의 광자전달

## 자료·코드 이용 (Data and code availability)

APEX는 오픈소스로 MIT 라이선스 아래 `https://github.com/Diu1773/APEX_AutomatedPhotometryEXtraction`에서 공개된다. `validation/paper/` 아래 검증 묶음은 각 그림 생성 스크립트와 `run_all.py`를 포함한다. 합성 자료만 사용하는 그림 6, 10, 11, 16은 고정 시드에서 다시 생성할 수 있고, 실측 자료가 포함된 그림 2–5, 7–9, 12–15, 17은 관측 자료 볼륨이 필요하다. 그림 15에 쓴 Pan-STARRS 1 교차매칭은 저장소에 캐시했다. 이 원고와 함께 두는 `references.bib`에 인용 문헌의 DOI를 기록했다.

## 소프트웨어 (Software)

이 연구는 Astropy \citep{astropy2013, astropy2018, astropy2022}, photutils \citep{photutils}, SEP \citep{barbary2016} 를 쓴다. 검출기 보정 교차검증의 Python 경로는 `ccdproc` 2.5.1 (\citet{ccdproc})이며, IRAF 경로는 IRAF `ccdred`의 `ccdproc` 태스크 (Tody 1986, 1993, \citep{tody1986,tody1993})를 PyRAF 2.2.3.dev9로 호출했다. astrometric solution은 내장 quad 솔버를 기본으로 쓰고, ASTAP \citep{astap} 와 astrometry.net \citep{lang2010} 을 외부 엔진으로 지원한다(3.6절). 독립 측광 교차 확인은 PyRAF를 통한 IRAF/DAOPHOT \citep{stetson1987} 를 쓴다. APEX의 검출기 보정 단계는 이 두 독립 구현 및 카메라 두 대의 LCO BANZAI 비교로 검증하였다(3.2절). 우주선·핫픽셀 제거는 astroscrappy \citep{vandokkum2001} 를 쓴다.
