# APEX 논문·출판 뷰어 구현 계획

이 문서는 국문 정본 `MANUSCRIPT_ko.md`를 기준으로 논문을 검증하고, A&A
Section 15 (Astronomical instrumentation and methods) 제출본으로 수렴시키기
위한 작업 순서와 뷰어의 기준 동작을 고정한다. 원고의 과학적 주장은
“중소형 지상망원경의 raw CCD 자료를 하나의 GUI 작업면에서 전처리·측성·측광·
CMD 또는 광도곡선까지 재현 가능하게 연결한다”는 한 문장으로 시작한다.

## 1. 논문 구현 게이트

### P0 — 주장과 범위 동결

* 입력은 raw FITS부터 시작하며, 출력은 CMD와 light curve이다.
* 내장 WCS 솔버가 기본 경로이고 ASTAP/astnet은 명시적 사용자 선택 옵션이다.
* APEX를 “최초”라고 주장하지 않는다. 차별점은 동일 GUI, 단계별 산출물,
  provenance, 중소형 망원경 환경에서의 재현성이다.
* 장비·필터·노출·검출 문턱·측광 반경·WCS 엔진과 버전을 표로 고정한다.

### P1 — 증거 목록과 데이터 계보

1. 각 본문 수치에 `fig_*.py`, 입력 데이터, 단위, 산출물 경로를 연결한다.
2. raw → bias/dark/flat → 검출 → WCS → aperture/PSF → 보정 → CMD/LC의
   단계별 manifest를 생성한다.
3. Python `ccdproc`와 IRAF/PyRAF 경로를 패키지명·버전·동일 입력으로 분리해
   기록한다. “같은 패키지” 또는 “동일 결과”라고 쓰지 말고 실제 수치와
   차이를 표에 넣는다.

### P2 — 검증과 그림 재조판

* bias/dark/flat은 대표 프레임, 통계량(중앙값/MAD), 잔차 지도로 나눈다.
* 그림의 (a)–(d)는 캡션에서 각각 목적·축·표식·판정 기준을 설명한다.
* 검출 완전도와 검출 문턱/핫픽셀 오염은 “방법 → 결과” 순서로 재배치한다.
* WCS는 내장 솔버 성공률·잔차와 ASTAP/astnet 선택 경로를 별도 비교한다.
* 측광오차모형은 정의·추정식·외부 검증을 먼저 제시하고 그림 7b를 핵심
  검증 패널로 위치시킨다.
* 큰 표와 그림은 단을 억지로 쪼개지 않고 `table*`/`figure*` float로 둔다.

### P3 — 원고와 A&A 산출물

* 1쪽 표지, 2쪽 목차/그림목록, 3쪽 초록+2단 본문을 고정한다.
* `build_paper.py`가 정본에서 XeLaTeX/LuaLaTeX용 `latex/review.tex`와
  PDF를 함께 생성한다. TeX 엔진이 없는 개발 환경에서는 PyMuPDF fallback을
  사용하되, 상태 파일에 엔진과 한계를 명시한다.
* 실제 제출 직전에는 A&A 공식 클래스와 참고문헌 스타일로 한 번 더 빌드하고,
  국문 검토본과 영문 제출본의 수치·그림 번호를 대조한다.

### P4 — 재현성·성능·윤리 점검

* 전체 파이프라인을 새 환경에서 한 번 실행하고, seed·시간대·좌표계·단위를
  기록한다. 미래 정보가 검출/보정 단계에 누출되지 않는지 확인한다.
* IO, pandas groupby/apply, 큰 NumPy 배열 계산을 프로파일링한 뒤, 개선 전후의
  wall time·peak RAM·결과 checksum을 남긴다. 빠르다는 이유만으로 native
  엔진을 정당화하지 말고, 정확도·의존성·설치성·병목 수치로 설계 근거를
  제시한다.
* 공개 저장소에는 raw 관측자료·개인 경로·비공개 검증자료를 넣지 않는다.
  공개 manifest에는 파일 해시와 재생산 명령만 둔다.

### P5 — 심사 전 점검

* A&A Section 15의 형식, 데이터/코드 공개, AI 사용 고지, 이해상충, 참고문헌
  DOI를 확인한다.
* 독립 검토자가 raw 한 세트로 CMD와 LC를 재생성하고, 표·그림·본문 수치가
  일치하는지 확인한다.

## 2. 뷰어 구현 기준

`paper_viewer.html`은 두 산출물을 같은 창에서 전환한다.

* `PDF`: `build/review/APEX_review.pdf`를 브라우저의 실제 PDF 뷰어로 연다.
* `판면 HTML`: 페이지 경계·여백·바닥글(`p / N`)을 보존하면서 모든 쪽을
  연속으로 스크롤한다. `Ctrl/Cmd + 휠`은 확대/축소, `Shift + 휠`과
  `A/D`는 좌우 패닝, `M`은 메모, `P`는 연속/한 쪽 보기 전환이다.
* 메모는 원고 인용문을 anchor로 localStorage에 보관하며, 조판이 다시 되어도
  메모 목록이 자동으로 사라지지 않는다.
* 페이지 수와 현재 쪽은 HUD에서 항상 `현재 / 전체`로 보인다. 큰 그림/표는
  페이지 경계를 넘지 않도록 별도 float 페이지를 사용할 수 있다.

## 3. 완료 조건

`build_paper.py` 실행이 정본 해시·엔진·페이지 수를 `build/review/build_status.json`
에 기록하고, 표지/목차/초록+2단/페이지 번호가 PDF와 HTML에서 모두 보이면
P0–P3을 통과한다. 이후 수치 계보, 외부 비교, 성능 기록, A&A 형식 검토가
완료되어야 논문 초안을 “제출 준비”로 표시한다.
