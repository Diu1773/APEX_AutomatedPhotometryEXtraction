# §1 서론 — 사용자 집필본 검토 (2026-08-27)

사용자가 §1 을 직접 썼다. Claude 초안(`DRAFT_S1_20260826.md`)은 **폐기**하고
사용자 집필본을 정본으로 한다. 아래는 왜 그게 나은지와 남은 작업.

## 사용자 집필본이 더 나은 이유

**1. 원체험을 뺐다.** 1.1 이 「서로 다른 시점과 조건에서 얻은 측정값을 일관된
자료로 묶는 문제」로 논지를 세운다. 일화 없이 선다. 심사가 지적한 교란 변수
넷(과제 난이도·동기·학습 상태·공동체 나이)이 애초에 생기지 않는다.
**→ D-P05(원체험 인칭)는 이걸로 닫힌다. 원체험을 안 쓴다.**

**2. 논지를 source identity 로 잡았다.**
> 한 프레임에서 생성한 검출목록보다 여러 프레임을 지나면서 유지되는
> source identity 가 분석의 기준이 된다.

ARS 악마의 변호인이 「21 개 소절 중 다른 패키지가 쓸 수 없는 이름이 하나도
없다」고 한 문제를 서론에서 푼다. 그리고 ALLFRAME(Stetson 1994)을 master star
list 맥락에 붙여 **요구받은 인용을 채우면서 동시에 APEX 고유 개념을 선행연구
계보에 접붙였다.** §2·§3 절 이름을 이 축으로 다시 볼 수 있다.

**3. PhoPS 선점을 정직하게 처리했다.** 「지역 Gaia 자료를 동적으로 이용해
대규모 사전 astrometric index 의 필요를 줄인 것처럼」 — 선점 인정 + 차이 명시.
그리고 **「오프라인」이라고 안 썼다.** `wcs_solve.py:2776` 이 인터넷을 요구하므로
오프라인 주장은 사실이 아니었고, 이 문장은 정확하다.

부수: Windows 데스크톱 빌드라는 배포 형태 명시 / 1.3 의 「보고된 측광오차가 실제
잔차를 설명하는 정도」(심사에도 없던 항목) / 잔차 세 갈래를 서론에 미리 깖.

## 남은 작업

### 근거 확인이 필요한 것

- **수업 사용자 분석·설문** — 1.3 마지막이 이걸 **이미 한 일로** 쓴다.
  2026-08-27 확인: 레포 전체와 Claude 메모리 폴더 어디에도 APEX 수업 설문 기록이
  없다. 매치된 것은 전부 다른 것이었다 — `asassn_period_survey.csv`(관측 서베이) ·
  `lco_ngc6811_ubv_survey.py`(관측 서베이) · `ROADMAP.md` 의 「수업기간」(1 인 개발
  리스크) · EASWA 프로젝트의 설문.
  **있으면 이 논문의 가장 강한 자산 중 하나다** — 심사가 「저자가 재면 증거가
  안 된다」고 지적한 자리를 정확히 메운다. 자료 위치 확인 필요.

### 서론이 약속하는데 코드에 없는 것

- **허위검출(오검출률) 검사** — 완전도는 인공별로 재지만 오검출률 측정이 없다
- **프레임 간 source association 의 누락과 오대응** — 짝짓기 검증 코드가 없다
- **외부 성단원 목록 입력 경로** — `apex/gui/tools/cluster_structure/` 는 독립
  도구이고 CMD 스텝이 부르지 않는다. §4 CMD 를 외부 목록으로 제한했다고 쓰려면
  그 경로가 있어야 한다
